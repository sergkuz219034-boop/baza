# Быстрый старт

## Маршрут для нового разработчика

1. Прочитать [[00_Главное/Главная/Обзор проекта|Обзор проекта]].
2. Открыть [[00_Главное/Старт/Структура репозитория|Структура репозитория]].
3. Пройти [[02_Код/Архитектура/Обзор системы|Обзор системы]] и [[02_Код/Архитектура/API|API]].
4. Для runtime-layer открыть [[02_Код/Эксплуатация/Конфигурация|Конфигурация]] и [[02_Код/Эксплуатация/Воркеры и расписание|Воркеры и расписание]].
5. Для first-debug использовать [[03_Ошибки/Отладка/Рецепт отладки|Рецепт отладки]].

## Канонические входы

- live source repo: `/root/TrafficHub`
- wiki: этот vault
- imported engineering archive: [[04_План/Материалы/сырьё/документы/TrafficHub-obsidian/README|TrafficHub-obsidian]]

## Минимальный onboarding flow

1. Понять карту системы по [[02_Код/Архитектура/Обзор системы|Обзору системы]].
2. Зафиксировать реальные точки входа по [[02_Код/Код/Бэкенд|Бэкенду]] и [[02_Код/Код/Инфраструктура|Инфраструктуре]].
3. Сверить runtime-маркеры в [[02_Код/Эксплуатация/Конфигурация|Конфигурации]].
4. Для любой живой проблемы идти через [[03_Ошибки/Отладка/Рецепт отладки|Рецепт отладки]], а не через случайный grep по vault.
5. Если работа планируется именно по `Autolead`, сразу открыть [[01_Правила/ИИ/Workflow Codex для Autolead|Workflow Codex для Autolead]].

## Чего не делать

- не воспринимать `baza` как source repo приложения;
- не менять канон на основе неподтверждённой старой заметки;
- не описывать систему как single-db/single-process, если live runtime показывает другое.
