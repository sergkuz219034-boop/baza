# Рефакторинг

- упрощение границы между legacy `api/*` и новым `traffic_hub/*`
- сокращение количества fallback storage paths
- вынос повторяемых debug/playbook контрактов в короткий канон

## Ближайший storage refactor stream

- `utils/database.py`: сделать границу между PostgreSQL runtime и SQLite fallback явнее, чтобы production path читался без полного прохода по всему модулю;
- `utils/runtime_repository.py`: вынести или хотя бы жёстко пометить SQLite read fallback как отдельный compatibility path;
- `services/stats_service.py`: определить, нужен ли SQLite-only path для postback-метрик в live-контуре;
- `utils/runtime_store_schema.py` и `utils/runtime_store_maintenance.py`: решить, остаются ли они production-adjacent или переводятся в legacy-only слой.

## Что не смешивать

- cleanup `autolead runtime` fallback-кода;
- отдельный migration stream `utils/control_store.py` и `control.db`.
