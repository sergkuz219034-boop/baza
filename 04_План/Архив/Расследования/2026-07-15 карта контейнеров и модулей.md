# 2026-07-15 карта контейнеров и модулей

Теги: #architecture #live

## Симптом

Нужна актуальная карта контейнеров и модулей TrafficHub, их взаимодействий и план ускорения продукта, разработки и дебага.

## Зона системы

- Live Docker Compose contour и public ingress.
- Server repo `/root/TrafficHub`: entrypoints, routers, services, storage, worker и интеграции.

## Гипотеза

Основные точки задержки и сложности лежат на границах Caddy → сервисы → PostgreSQL/Redis/external API, а также в разрозненных процессах bot/worker.

## Проверка

- Выполняется verified fallback scan live repo и runtime. Изменения product runtime не выполняются.

## Наблюдение

- Live stack содержит 11 compose services: Caddy, autolead bot, worker, PostgreSQL, Redis, Account Manager, license auth/server, operator CRM, HR AI worker и standalone content bot.
- Caddy — единственный public ingress. `traffic-hub.pro` проксирует в `autolead_bot`; `am.*` — в Account Manager; `auth.*` — в license auth; `/license/*` — в license server; operator/manager SPA обращается к Autolead по `/api`, `/auth`, `/ws`.
- `autolead_bot` запускает `main.py` → `api/server.py`, который подключает legacy routers `/api/*` и регистрирует `traffic_hub/app.py` с `/traffic-api/*` routers. Это подтверждённая смешанная application boundary.
- Worker использует Redis keys `traffic_hub:jobs:*` и запускает owner-scoped subprocess `traffic_hub.job_process`; `WORKER_MAX_PARALLEL_OWNERS=2` ограничивает одновременную работу owners.
- PostgreSQL — основной storage для product, control store и runtime stores; Redis — очередь/state. `postback_logs` занимает 57 MB, крупнейшая таблица в DB.
- `pg_stat_statements` показывает: owner config reads 362 538 calls / ~1 064 s; logs reads 119 806 calls / ~54 млн returned rows; широкая leads selection mean ~122 ms.
- CI содержит 87 Python test files, но использует одновременно несколько workflows (`ci.yml`, `project-checks.yml`) с близкими проверками.

## Вывод

Карта подтверждена в [[02_Код/Архитектура/Карта контейнеров и модулей]]. Главная причина высокой cognitive load — coexistence legacy Autolead API и нового traffic-core в одном контейнере и общем image. Главная подтверждённая performance surface — слишком частые reads конфигурации и большого лога, а не CPU/Redis/PostgreSQL health.

## Следующий шаг

1. Измерить endpoint-level p95/p99 и выполнить `EXPLAIN (ANALYZE, BUFFERS)` для config/log/leads запросов до изменения индексов.
2. Выбрать один vertical slice для выделения из legacy API без отдельного масштабного rewrite.
3. Добавить единый correlation/job ID в API, worker и external client logs.
