# Фоновые задачи

## Подтверждено

- фоновое исполнение вынесено в отдельный worker;
- worker работает через Redis queue;
- модель параллелизма — subprocess-per-owner.

## Что входит в фоновые контуры

- owner job execution в `traffichub_worker`;
- status publish loop в web/API;
- partner sync loop внутри lifespan `api/server.py`;
- stop orchestration через owner-scoped Redis keys и signals.

## Риски

- фоновые циклы живут не только в worker, но и внутри web/API процесса;
- restart одного контейнера не доказывает восстановление всего runtime-контура;
- stale owner state нужно проверять отдельно от бизнес-ошибок оффера.
