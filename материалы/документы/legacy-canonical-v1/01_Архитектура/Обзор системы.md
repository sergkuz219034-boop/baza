# Обзор системы

## Канон

- `TrafficHub` — гибридный серверный проект;
- live mutable repo находится в `/root/TrafficHub`;
- `baza` хранит краткий project-layer и сопутствующие рабочие знания.
- live `HEAD` на `2026-06-16`:
  - `a8f0be217fc7f23b8af6dead50b9968c9620cea1`

## Подтверждённые узлы

- legacy слои `api/`, `services/`, `modules/`, `utils/`;
- новый слой `traffic_hub/*`;
- отдельный `AccountManager/`;
- runtime разделён на web, worker, PostgreSQL, Redis, license/auth и Caddy.

## Точки входа

- web/dashboard/auth/websocket: `/root/TrafficHub/api/server.py`
- router map и embedded API: `/root/TrafficHub/traffic_hub/app.py`
- owner jobs: `/root/TrafficHub/traffic_hub/worker.py`
- queue orchestration: `/root/TrafficHub/traffic_hub/services/job_queue.py`
- run execution: `/root/TrafficHub/traffic_hub/services/job_runner.py`
- tenant isolation tests: `/root/TrafficHub/tests/test_traffic_tenant_isolation.py`

## Основные инварианты

- локальный `traffichubserver` workspace не равен исходному коду приложения;
- `TrafficHub` нельзя описывать как one-process или one-db систему;
- owner-scoped модель данных и исполнения является частью архитектуры, а не частной реализацией.
- `TrafficHub` надо отделять от соседних host-проектов `/root/freellmapi`, `/root/hermes-webui`, `/root/hermes-workspace`, `/root/mfo`, `/root/content-poster-bot`.
- live `TrafficHub` worktree после cleanup снова clean.
