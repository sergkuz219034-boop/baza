# Анализ логов

## Что смотреть

- web/API logs
- worker logs
- Redis owner-state
- websocket/status bridge

## Что считать нормой

- сразу после запуска есть owner-scoped строки `в очереди` и `запущен`;
- для длинной job heartbeat приходит примерно раз в `15` секунд;
- финальный статус должен остаться в истории;
- обычные log lines не должны удалять runtime spinner/status строку.

## Ожидаемые статусные сообщения

- `Полный цикл: в очереди`
- `Полный цикл: запущен`
- `Полный цикл: выполняется`
- `⛔ Полный цикл остановка`
- `⛔ Полный цикл остановлен`
- `Полный цикл: завершён`

То же правило относится к `Рассылка`, `Выгрузка` и другим owner jobs.

## Что не считать нормой

- тишина в live-логе при живом `running` без heartbeat;
- пропажа финального статуса после успешного завершения;
- многострочные Playwright `Call log` в пользовательской ленте;
- чужие owner-логи в чужом `app_log`.
