# 2026-06-15 `utils.state` больше не зависит жёстко от `pydantic_settings` для тестов

## Симптом

`tests/test_retry_queue_matching.py` падал не из-за retry-logic, а уже на импорте:

- `utils.state`
- `traffic_hub.config.settings`
- `from pydantic_settings import BaseSettings`

При этом `requirements.txt` уже содержит `pydantic-settings`, но в фактическом test-env серверного `python3` модуль отсутствовал.

## Зона системы

- test environment
- `utils/state.py`
- `traffic_hub/config/settings.py`
- retry queue tests

## Гипотеза

Проблема не в самой retry queue, а в лишней связности:

- `utils.state.py` нужен только `redis_url`;
- ради этого он безусловно тянул весь `traffic_hub.config.settings`.

Если разрешать Redis URL лениво и с env fallback, то:

- `utils.state` перестанет ломать тесты при отсутствии `pydantic_settings`;
- coupling между state-layer и `traffic_hub` уменьшится.

## Проверка

На live source сервера подтверждено:

- `utils/state.py` использовал `settings.redis_url` только в `_client()`;
- `python3 -c "import importlib.util; print(importlib.util.find_spec('pydantic_settings'))"` вернул `None`;
- после изменения `utils/state.py` на lazy `_resolve_redis_url()` с fallback:
  - `python3 -m compileall -q utils/state.py ...`
  - `python3 -m pytest -q tests/test_retry_queue_matching.py -q`
  - `python3 -m pytest -q tests/test_database.py -q`

## Наблюдение

- `tests/test_retry_queue_matching.py` стал зелёным.
- Причина была в import-time dependency, а не в retry-queue logic.
- Дополнительной установки пакета для подтверждения fix не потребовалось.

## Вывод

Исправлена не только test-env ошибка, но и архитектурная лишняя связность:

- state-layer больше не зависит жёстко от `traffic_hub.config.settings` на import-time;
- Redis URL разрешается по факту использования.

## Следующий шаг

1. Проверить, нет ли аналогичных import-time зависимостей в других utility-модулях.
2. Не тянуть тяжёлые config-модули в helpers, если нужен один параметр.
3. При дальнейшей чистке тестов отделять проблемы test-env от бизнес-логики и storage split.
