## Симптом

- Пользователь `admin` после смены пароля не может войти в TrafficHub.
- UI возвращает `Неверный логин или пароль`.

## Зона системы

- `api/server.py`
- `utils/license.py`
- PostgreSQL auth source (`users.hashed_password`)

## Гипотеза

- В production auth идет через PostgreSQL, и текущий hash для `admin` больше не соответствует паролю `cryptO2190$`.

## Проверка

- Live code:
  - `utils/license.py::validate_user()`
    - при `_postgres_license_enabled()` проверяет только PostgreSQL `users.hashed_password`
  - `utils/license.py::set_user_password()`
    - в PostgreSQL-режиме обновляет пароль через `_pg_set_password(...)`
- Live runtime:
  - `validate_user('admin', 'cryptO2190$') -> False`
- После серверного reset:
  - `set_user_password('admin', 'cryptO2190$')`
  - `validate_user('admin', 'cryptO2190$') -> True`

## Наблюдение

- Проблема была не в login route и не в rate limit.
- Runtime просто не принимал введенный пароль, потому что текущий PostgreSQL hash уже был другим.

## Вывод

- Для `admin` произошел runtime password mismatch.
- Подтверждено восстановление входа после reset штатной серверной функцией `set_user_password()`.

## Следующий шаг

- Если проблема повторится, логировать успешную смену пароля отдельно от UI-notification:
  - кто сменил;
  - когда;
  - для какого username;
  - прошла ли post-change валидация `validate_user(username, new_password)`.
