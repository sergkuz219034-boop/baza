# 2026-06-17 Карта интеграций live code

## Симптом

- страница `[[02_Архитектура/Интеграции]]` была слишком общей;
- не было короткой канонической карты, какие интеграции реально подтверждены live-кодом и как они разделены по контурам.

## Зона системы

- product API integrations
- legacy Rabota/Sheets contour
- postback/import contour

## Гипотеза

- в системе есть не одна интеграционная поверхность, а минимум три:
  - product `traffic_hub` integrations через `/traffic-api/settings/integrations`
  - legacy Rabota/Google Sheets execution path в `services/*` и `modules/*`
  - import/postback contour для внешних данных

## Проверка

- просмотрен live source tree `/root/TrafficHub`:
  - `traffic_hub/api/routers/integrations.py`
  - `modules/sheets_sync.py`
  - `modules/rabota_api.py`
  - `api/routers/avito.py`
  - `api/routers/control.py`
  - `services/leads_service.py`

## Наблюдение

- `traffic_hub/api/routers/integrations.py`:
  - product router живёт на `prefix="/traffic-api/settings/integrations"`;
  - подтверждены сети `leadsu`, `lovko`, `pampadu`;
  - credentials и status хранятся в `NetworkIntegration` плюс user config через `control_store`;
  - postback token генерируется для `leadsu` и `pampadu`;
  - есть endpoints чтения, patch, reset/regenerate postback и test.
- `modules/sheets_sync.py`:
  - legacy Google Sheets слой живёт отдельно;
  - поддерживает pending/processed queue bindings;
  - `get_sheets_offers_for_offers(...)` читает вакансии из таблицы и умеет dedupe с Rabota vacancies.
- `modules/rabota_api.py`:
  - `RabotaRuClient` сначала пытается читать user-scoped cloud credentials;
  - file fallback остаётся только вне user-context;
  - токен refresh и network diagnostics встроены в сам клиент.
- `api/routers/avito.py` + `modules/avito_import.py`:
  - Avito — это не realtime partner API, а import contour;
  - строки Avito нормализуются и затем грузятся в Google Sheets через `upload_to_sheets(...)`.
- `api/routers/control.py`:
  - `POST /import-legacy-sheets` импортирует текущие Google Sheets control data в control store backend.
- `services/leads_service.py`:
  - legacy full cycle всё ещё опирается на Rabota + Google Sheets path;
  - product integrations и legacy operational integrations нельзя описывать как один и тот же слой.

## Вывод

- интеграции надо делить минимум на четыре класса:
  - product network integrations: `leadsu`, `lovko`, `pampadu`
  - legacy operational integrations: `Rabota.ru`, `Google Sheets`
  - import bridge: `Avito`
  - external bridge: `AccountManager`
- отдельный postback contour уже живёт в product DB и не равен legacy operational path.

## Следующий шаг

- обновить `[[02_Архитектура/Интеграции]]`;
- при следующих расследованиях сразу различать product integrations и legacy operational integrations, чтобы не смешивать их в одну причину бага.
