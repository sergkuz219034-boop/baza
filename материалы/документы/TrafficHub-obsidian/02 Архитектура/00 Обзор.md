# Обзор

- Локально доступны code/runtime fragments:
  - `artifacts/remote_edit/api/server.py`
  - `artifacts/remote_edit/api/ws_manager.py`
  - `artifacts/remote_edit/traffic_hub/worker.py`
  - `artifacts/remote_sync/docker-compose.yml`
  - `license_server/app.py`
- Полный checkout `/root/TrafficHub` локально отсутствует.
- На `2026-06-11` выполнен live SSH sync против `/root/TrafficHub`, поэтому текущие факты по compose/auth/job queue уже подтверждены не только snapshot-ом, но и live-кодом.
- На `2026-06-16` выполнена поэтапная live-миграция Autolead runtime storage в PostgreSQL. Подтверждение: [[материалы/документы/TrafficHub-obsidian/05 Решения/2026-06-16 Мигрировать Autolead runtime поэтапно начиная с логов]].
- Подробности и ограничения: [[материалы/документы/TrafficHub-obsidian/01 Расследования/2026-06-11 Локальный evidence bundle и границы канона]].
- Live-результат сверки: [[материалы/документы/TrafficHub-obsidian/01 Расследования/2026-06-11 Live server sync и расхождения compose-access]].

## Что подтверждено

- Продовый проект живёт в `/root/TrafficHub`.
- Публичный backend адресуется через `https://traffic-hubcrm.ru`.
- Live source of truth — гибридный монорепозиторий, а не один backend.
- Live `api/server.py` подтверждает основной health endpoint `/api/health`.
- Live health на `2026-06-11` отвечает:
- Live health на `2026-06-16` отвечает:
  - `control.backend=postgres`
  - `control.legacy_import_enabled=false`
- Текущий server contour не one-process:
  - web/API: контейнер `autolead_server_bot`
  - worker: контейнер `traffichub_worker`
  - queue/state bus: `traffichub_redis`
  - primary DB: `traffichub_postgres`
  - auth/license: `traffichub_license_auth`, `traffichub_license_server`
  - account manager: `traffichub_account_manager`
  - reverse proxy: `traffichub_caddy`

## Границы подсистем

### 1. Dashboard / API

- Локально подтверждённый код: `artifacts/remote_edit/api/server.py`
- Назначение:
  - HTML/JS dashboard
  - `/api/*`
  - `/auth/login`
  - `/ws/log`
  - `/ws/status`
- Подтверждённые auth-факты:
  - REST router-ы `leads/jobs/stats/settings/offers/system/debug/avito/control` подключаются с dependency `authenticate_basic_credentials`;
  - сессионная cookie называется `traffichub_session`;
  - есть совместимые пары endpoint-ов `/auth/*` и `/api/auth/*`.
  - WebSocket контур `/ws/log` и `/ws/status` работает через session principal, а не через реальный Basic token parsing.

### 2. Autolead execution

- Канонический код этого слоя находится на сервере в `/root/TrafficHub`.
- Назначение:
  - сбор Rabota.ru / SuperJob / Avito import
  - экспорт в Google Sheets
  - Playwright form fill
  - retry queue
- Active runtime storage в production PostgreSQL-backed через env:
  - `AUTOLEAD_RUNTIME_LOGS_BACKEND=postgres`
  - `AUTOLEAD_RUNTIME_DELIVERY_BACKEND=postgres`
  - `AUTOLEAD_RUNTIME_LEADS_BACKEND=postgres`
  - `AUTOLEAD_RUNTIME_AUTOFIT_BACKEND=postgres`
  - `AUTOLEAD_RUNTIME_INVITES_BACKEND=postgres`
  - `AUTOLEAD_RUNTIME_CONTROL_SYNC_BACKEND=postgres`
- SQLite остаётся fallback/test/legacy compatibility backend, а не production source of truth.
- PostgreSQL runtime tables:
  - `autolead_app_log`
  - `autolead_run_log`
  - `autolead_send_history`
  - `autolead_retry_queue`
  - `autolead_leads`
  - `autolead_autofit_seen`
  - `autolead_invite_history`
  - `autolead_invite_message_state`
  - `autolead_control_sync_queue`

### 3. Job queue и worker

- Локально подтверждённый код: `artifacts/remote_edit/traffic_hub/worker.py`, `artifacts/remote_edit/api/ws_manager.py`
- `job_queue.py` и `job_runner.py` в bundle отсутствуют, но их использование подтверждено imports в worker/web API и расследованиями.
- Назначение:
  - постановка user-scoped job в очередь
  - исполнение в отдельном worker-процессе
  - публикация статусов в Redis + websocket
- runtime-ограничение:
  - state и stop-flag остаются owner-scoped;
  - фактическое исполнение jobs в одном `traffichub_worker` сейчас последовательное;
  - причина подтверждена расследованием [[материалы/документы/TrafficHub-obsidian/01 Расследования/2026-06-11 Autolead owner-scoped jobs и UI-логи]]: `redirect_stdout()` в job runtime не потокобезопасен для owner-scoped app-log.

### 4. Control/Auth layer

- Локально видимый код:
  - `artifacts/remote_edit/api/server.py`
  - `license_server/app.py`
- Полные модули `utils/control_store.py`, `utils/license.py`, `api/authz.py`, `api/autolead_access.py` в bundle отсутствуют.
- Назначение:
  - пользователи, роли, auth secrets, config merge
  - authn/authz для dashboard и jobs/settings/leads
  - JWT bridge для Account Manager через `/api/account-manager/token`
- Нетривиальный факт:
  - вход в Account Manager разрешён всем аутентифицированным пользователям TrafficHub, а role restriction остаётся внутри самого Account Manager.

### 5. TrafficHub embedded/domain layer

- Локальный факт:
  - `register_traffic_hub(app)` вызывается в `api/server.py`;
  - live `traffic_hub/app.py` монтирует router-ы с prefix `/traffic-api/*`.
- Статус:
  - модуль существует в runtime wiring;
  - старая модель отдельной `/traffic/` SPA устарела;
  - `GET /traffic` и `GET /traffic/{path}` сейчас редиректят в `/` или `/#crm-finance`.
  - фактические mounted API prefixes:
    - `/traffic-api/auth`
    - `/traffic-api/leads`
    - `/traffic-api/offers`
    - `/traffic-api/finance`
    - `/traffic-api/messengers`
    - `/traffic-api/funnels`
    - `/traffic-api/click`
    - `/traffic-api/postbacks`
    - `/traffic-api/stats`
    - `/traffic-api/tools`
    - `/traffic-api/settings/integrations`

### 6. Background loops / scheduler

- Видимый runtime не использует отдельный внешний scheduler в исследованном фрагменте.
- Подтверждённые циклы в `artifacts/remote_edit/api/server.py`:
  - partner sync не вынесен в внешний cron по исследованному live-коду;
  - `_push_status_loop()` пушит job status каждые `2` секунды;
  - `_partner_sync_loop()` запускает sync партнёрских сетей раз в `3600` секунд через `asyncio.create_task()` внутри lifespan FastAPI.
- Следствие:
  - для расследования partner sync нужно смотреть не cron, а lifecycle web/API процесса.

## Поток управления jobs

1. UI вызывает `POST /api/jobs/run`
2. `api/routers/jobs.py` валидирует роль и доступ
3. `traffic_hub/services/job_queue.py` пишет owner-scoped state и Redis queue
4. `traffichub_worker` забирает job
5. `traffic_hub/services/job_runner.py` вызывает `services/leads_service.py`
6. status публикуется через Redis event bridge
7. `api/server.py` ретранслирует status в `/ws/status`
8. `dashboard/app.js` обновляет pill и кнопки

## Что устарело

- Утверждение `один Python-процесс — всё в памяти` устарело.
- Утверждение `control.db — основной источник пользователей` устарело.
- Утверждение `вся система уже migrated в PostgreSQL` раньше было преждевременным. По состоянию на `2026-06-16` подтверждено точнее:
  - control/auth — PostgreSQL-backed;
  - Autolead active runtime — PostgreSQL-backed;
  - SQLite остаётся fallback/test/legacy compatibility layer;
  - AccountManager может иметь отдельный storage contour и проверяется отдельно.
- Утверждение `SQLite как основной state layer` устарело:
  - Autolead active runtime tables перенесены в PostgreSQL;
  - runtime control store уже PostgreSQL-backed;
  - Redis используется как канонический канал для queue/status/stop flags.
- Утверждение про отдельную активную `/traffic/` SPA устарело:
  - локальный server fragment показывает redirect-only поведение.
