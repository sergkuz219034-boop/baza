# Каталог ошибок

## Что сюда входит

- повторяемые runtime/business/infra ошибки
- типовые симптомы
- первый known-good check

## Минимальный формат записи

- симптом
- затронутый слой
- первый check
- confirmed cause или статус `гипотеза`
- ссылка на расследование или баг-заметку

## Когда обновлять

- когда ошибка повторяется больше одного раза;
- когда найден новый быстрый discriminating check;
- когда старый воркараунд больше не соответствует live системе.

## Повторяющаяся ошибка мышления

### Симптом

- инженер или агент видит `autolead.db` или `control.db` и делает вывод, что live runtime сейчас работает через SQLite.

### Затронутый слой

- runtime diagnosis
- storage boundary
- incident triage

### Первый check

- проверить `docker-compose.yml` и effective env:
  - `AUTOLEAD_RUNTIME_LOGS_BACKEND`
  - `AUTOLEAD_RUNTIME_DELIVERY_BACKEND`
  - `AUTOLEAD_RUNTIME_LEADS_BACKEND`
  - `AUTOLEAD_RUNTIME_AUTOFIT_BACKEND`
  - `AUTOLEAD_RUNTIME_INVITES_BACKEND`
  - `AUTOLEAD_RUNTIME_CONTROL_SYNC_BACKEND`
- проверить, какой backend возвращает `control_store` status;
- отделить `autolead runtime`, `control_store` и `traffic_hub` product DB.

### Confirmed cause

- в текущем live-контуре SQLite-артефакт может быть compatibility/fallback/legacy слоем, а не production source of truth.

## AccountManager scheduler: offset-naive vs offset-aware datetime

### Симптом

- в `docker logs traffichub_account_manager` появляется:
  - `account_manager.scheduler ERROR: Google scheduler tick failed`;
  - `TypeError: can't subtract offset-naive and offset-aware datetimes`.

### Затронутый слой

- `AccountManager/scheduler.py`;
- PostgreSQL `DateTime(timezone=True)` fields у Account Manager models;
- APScheduler background checks.

### Первый check

- `docker logs --since 12h traffichub_account_manager | rg -i 'scheduler tick failed|offset-naive|offset-aware|Traceback'`;
- проверить сравнения в `AccountManager/scheduler.py`: `last_checked`, `last_active`, `flood_wait_until`;
- прогнать `pytest -q tests/test_account_manager_scheduler_timezones.py tests/test_access.py tests/test_scheduler_config.py`.

### Confirmed cause

- scheduler сравнивал timezone-aware значения из БД с naive `datetime.utcnow()`;
- при наличии aware timestamp Python запрещает вычитание/сравнение aware и naive datetimes.

### Исправление

- `AccountManager/scheduler.py` переведён на `_utc_now() = datetime.now(timezone.utc)`;
- legacy naive значения нормализуются через `_as_utc()`;
- добавлен regression test `tests/test_account_manager_scheduler_timezones.py`;
- full CI на commit `3c16fe3c2` зелёный;
- live `traffichub_account_manager` пересоздан, новых scheduler exceptions в свежем окне логов нет.

## Autolead retry timeout noise

### Симптом

- В логах повторяются красные ошибки `Page.goto: net::ERR_TIMED_OUT` для `tracking.lovko.pro`.
- В логах Leads.su может быть `Internal server error: Timeout expired... server is not responding`.
- Ошибки видны у разных owner, например `admin`, `alex`, `artem`.

### Затронутый слой

- `modules/vbiv_bot.py`
- `modules/platforms/leadsu.py`
- `services/leads_service.py::process_retry_queue`
- PostgreSQL `autolead_retry_queue`

### Первый check

- Проверить, не совпадает ли ошибка с коротким deploy/restart окном.
- Проверить активные retry-записи: `select owner_username, phone, offer_name, retry_count, max_retries, next_retry_at, error_msg from autolead_retry_queue order by next_retry_at;`
- Проверить, что ошибка не помечается permanent form-failure.

### Confirmed cause

- Внешние партнёрские timeout Lovko/Leads.su могут быть временными.
- Без ограничения пачки retry полный цикл может повторять много просроченных строк сразу и создавать шум в логах.

## Lovko short tracking: `Page.goto: net::ERR_TIMED_OUT`

### Симптом

- ошибка вида:
  - `Ошибка Я еда [N]: Страница оффера не открылась: Page.goto: net::ERR_TIMED_OUT at https://tracking.lovko.pro/<code>`;
- чаще проявляется на коротких Lovko tracking-ссылках без `offer_id=`.

### Затронутый слой

- `modules/vbiv_bot.py`;
- Lovko offer navigation;
- Playwright browser proxy;
- external partner tracking/landing.

### Первый check

- проверить, что owner имеет browser form proxy:
  - `rabota_ru.proxy_enabled=True` + `rabota_ru.proxy_url`;
  - или `vbiv.form_proxy_enabled=True` + `vbiv.form_proxy_url`;
  - `_playwright_proxy_from_config(config)` возвращает `proxy`;
- проверить, что `curl -I https://tracking.lovko.pro/<code>` возвращает `302 Location`;
- проверить, что финальный `Location` открывается в Chromium через Playwright proxy.

### Confirmed cause

- Chromium может зависать на коротком `tracking.lovko.pro/<code>` до перехода по `302`;
- при этом лёгкий HTTP preflight быстро получает `Location`;
- финальный landing может требовать proxy, но browser fill должен быть proxy-enabled только при включённом proxy-toggle.

### Исправление

- product commit: `c69420503 fix: preflight lovko short tracking redirects`;
- product commit: `786f38443 fix: respect proxy toggle for browser forms`;
- короткие Lovko tracking URLs предварительно резолвятся через `_resolve_lovko_tracking_redirect()`;
- браузер открывает финальный landing URL; Playwright proxy используется только если включён `rabota_ru.proxy_enabled` или `vbiv.form_proxy_enabled`;
- tests: `tests/test_vbiv_bot_runtime_errors.py`, `tests/test_vbiv_bot_navigation.py`, `tests/test_proxy_config.py`.

## Lovko final landing: `vakansii-ozon.ru` / `onecta-rabota.ru` timeout

### Симптом

- ошибка вида:
  - `Ошибка Ozon [N]: Страница оффера не открылась: Page.goto: net::ERR_TIMED_OUT at https://vakansii-ozon.ru/...`;
  - `Ошибка Onecta #2 [N]: Страница оффера не открылась: Page.goto: net::ERR_TIMED_OUT at https://onecta-rabota.ru/...`.

### Затронутый слой

- `modules/vbiv_bot.py`;
- Lovko final landing domains;
- Playwright browser proxy routing.

### Первый check

- проверить, что owner имеет включённый browser form proxy:
  - `rabota_ru.proxy_enabled=True` + `rabota_ru.proxy_url`;
  - или `vbiv.form_proxy_enabled=True` + `vbiv.form_proxy_url`;
- проверить, что `_is_slow_lovko_route("Ozon", "https://vakansii-ozon.ru/...") == True`;
- проверить, что `_is_slow_lovko_route("Onecta #2", "https://onecta-rabota.ru/...") == True`;
- открыть final landing через Playwright proxy внутри `traffichub_app`.

### Confirmed cause

- финальные Lovko landing-домены `vakansii-ozon.ru`, `onecta-rabota.ru`, `you-courier.ru` могут таймаутить из server/browser contour без browser proxy;
- старый detection покрывал не все final landing domains и частично зависел от `platform == "lovko"`.
- `Page.goto: net::ERR_TIMED_OUT` приходит как Chromium navigation exception, а не обязательно как `PlaywrightTimeoutError`; если ловить только timeout-класс, slow-route прерывается после первой попытки.

### Исправление

- product commit: `40df8b3cc fix: route lovko landing domains through proxy`;
- product commit: `bd9f85094 fix: retry lovko navigation network timeouts`;
- Lovko final landing domains включены в slow-route и proxy routing;
- `Page.goto` network errors включены в retryable navigation errors;
- tests: `tests/test_vbiv_bot_navigation.py`.
