# Ошибка: commit не прошёл, следующие команды продолжились

## Контекст

Канонизация HH-импорта, PowerShell и локальный TrafficHub main.

## Симптом и доказательство

Первый git commit завершился Author identity unknown. Следующий git push сообщил Everything up-to-date, rev-parse вернул старый 1b7a2dbb. Серверная стадия упаковки поэтому получила старый SHA, хотя staged-файлы уже содержали изменения. Maintenance оставался on; работающие процессы не перезапускались.

## Коренная причина

Репозиторий не имел локальной Git identity. Разделение нативных команд точкой с запятой в PowerShell не останавливает цепочку при ненулевом exit code.

## Исправление

Установлена repo-local identity проверенного авторизованного GitHub-пользователя. Commit/push повторены с явной проверкой LASTEXITCODE. Runtime-файлы сверены с git show текущего origin/main; серверные образы пересобраны и маркированы правильным SHA до снятия maintenance. Финальный main=39b48c9b.

## Профилактика (обязательное правило)

После каждого commit/push проверять exit code и прекращать release при ошибке. SHA допускается к выпуску только после подтверждения публикации и совпадения staged-файлов с соответствующими git blobs. Проверка равенства SHA origin/main сама по себе не доказывает принадлежность staged-файлов этому коммиту.

## Проверка, что ошибка не повторяется

Финальный выпуск: source_matches_main=true, label текущего SHA на обоих закреплённых образах, hashes runtime=staged, app/worker healthy, maintenance off. В цепочках публикации добавлены явные fail-fast проверки.
