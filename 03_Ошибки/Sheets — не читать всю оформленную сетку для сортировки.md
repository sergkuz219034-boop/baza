# Ошибка: читать всю оформленную сетку для сортировки

## Контекст

Перед перестановкой 27 175 строк запрашивалась резервная метаинформация Google Sheets с includeGridData=true без ограничения диапазона.

## Симптом и доказательство

Проверочный процесс завершился без PRE_APPLY и без резервного файла. Docker OOMKilled=true, kernel сообщил memory-cgroup OOM с RSS около 1,9 GiB. Перестановки отправляются только после сохранения snapshot и PRE_APPLY, поэтому этот проход не записал ни одного moveDimension. App продолжил отвечать health=ok.

## Коренная причина

Неограниченное grid-data резервирование превысило память проверочного процесса. Размер занятых данных не ограничивает размер оформленной сетки.

## Исправление

Сохранять данные, обычную метаинформацию и исходную перестановку. Использовать native перемещения целых строк и обратную перестановку для отката, не переписывать значения. Если необходимо отдельно сохранять grid-data, ограничивать реальные диапазоны и читать порциями.

## Профилактика (обязательное правило)

Не запрашивать includeGridData для всего production workbook без оценки диапазона и памяти. После аварийного завершения проверять живой процесс и активных писателей перед удалением его точной осиротевшей lease. Idle в UI недостаточно для безопасной перестановки: отдельно подтвердить выход процесса задания.

## Проверка, что ошибка не повторяется

Повтор без полной сетки: сохранён private snapshot, применены 147 native moves, 27 175 строк сохранились целиком, нарушения дат 47 → 0, повторная сортировка no-op, health=ok.
