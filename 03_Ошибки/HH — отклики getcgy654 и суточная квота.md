# HH: отклики getcgy654 и суточная квота

Проверено на production 2026-10-02. Результат: keep; импорт откликов blocked до предоставления доступа к вакансиям.

## Наблюдение

Подключённый менеджер профиля getcgy654 получает от HH API 0 активных и 0 архивных вакансий. Это не доказательство отсутствия вакансий у всего работодателя: проверен доступ конкретного менеджера. Просмотры резюме при диагностике не выполнялись. Исправленный запрос квоты показал остаток 500 из 500.

## Исправление

Для запроса квоты используется employer.manager_id, а не идентификатор пользователя manager.id. Учитываются ограничения resume_view и resume_view_from_api.

Добавлена атомарная Redis-защита: максимум 500 уникальных резервирований просмотра за скользящие 24 часа на работодателя, общая для профилей и подключений. Повторный ID резюме не открывается. Резервирование выполняется до HTTP-запроса, поэтому неудачные попытки также консервативно учитываются. При 429 текущая партия сохраняется и импорт прекращается с паузой не менее 24 часов. При недоступности Redis обход защиты не разрешён.

Тесты без запросов HH: конкурентное резервирование 700 ID даёт ровно 500 разрешений; повторный ID, истечение окна и суточная пауза проверены. App и worker healthy, maintenance off. Рабочие задания других профилей не прерывались. Сохранены изменённые production-файлы; подготовлены закреплённые Docker-образы для последующего пересоздания контейнеров.

## Следующий шаг

В кабинете HH предоставить подключённому менеджеру доступ к вакансиям с откликами либо подключить правильного менеджера. Затем один раз проверить список доступных вакансий и импортировать отклики. Не запускать полный цикл многократно для проверки пустого списка.

Защита учитывает попытки TrafficHub, но не заменяет серверную квоту HH и не наблюдает просмотры в других приложениях или на сайте HH.
