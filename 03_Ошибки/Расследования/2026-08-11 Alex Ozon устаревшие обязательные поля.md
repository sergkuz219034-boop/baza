# Alex: Ozon блокировался устаревшими обязательными полями

## Симптом

У owner `alex` рассылка Ozon завершалась `отправлено=0`, `ошибок=1`. Сообщение повторялось: `lovko Ozon: required fields were not selected before submit` для `tip-kuzova`, `available_drivers_license`, `work_experience`.

## Зона системы

- Lovko/Ozon form automation: `modules/platforms/lovko.py`.
- Retry: `modules/vbiv_bot.py`, PostgreSQL `autolead_retry_queue`.
- Runtime-артефакты: `/root/TrafficHub/data/debug/debug_Ozon_20260811_112506.html`.

## Гипотеза

Код считает legacy select-поля обязательными, хотя партнёрская Ozon-форма их больше не отдаёт.

## Проверка

В HTML debug-артефакте есть только `lastname`, `firstname`, `gender`, `citizenship`, `birthdate`, `mobile_phone`, `vacancy_id`. Трёх legacy select-полей нет. В live-логах 11.08.2026 эта причина повторялась; в retry-очереди найдено 111 owner-scoped записей Alex с точным сообщением.

## Наблюдение

`_ozon_required_selects()` до фикса требовал отсутствующие поля, а `LovkoPlatform` завершал форму до submit. Ошибка не классифицировалась как постоянная, поэтому создавала шум повторов. Отдельные 462 `scheduled-backfill` Ozon являются плановой очередью, не ошибкой.

## Вывод

Commit `912f4d179` заменил legacy-список обязательных Ozon select на пустой контракт текущей формы; regression test закрепляет это поведение. Live `autolead_bot` и `worker` работают с этим SHA и healthy.

Перед восстановлением очереди сохранён CSV backup: `/root/TrafficHub/data/backups/alex-ozon-legacy-select-retries-20260811T090000Z.csv.gz`. Ровно 111 stale retry-записей Alex сброшены в `retry_count=0`, `error_msg=''`, `next_retry_at=now`; stale-сообщений после операции — 0.

## Следующий шаг

- Следующий owner-scoped цикл обработает восстановленные записи по новой форме.
- Не запускать ручной submit с реальным кандидатом без отдельного разрешения: он создаёт заявку на партнёрке.
- При изменении Ozon-формы сначала проверять новый debug HTML, затем обновлять контракт, а не добавлять обязательные селекторы по памяти.
