# Канонический формат резюме Rabota.ru

## Симптом

В основной таблице `RabotaRu_Leads_Основа` → `Все лиды` часть ячеек `Резюме` содержала прямой URL `https://www.rabota.ru/resume/<id>`. Такой URL не соответствует контракту выгрузки и не содержит контекст отклика.

## Зона системы

- Нормализация: `utils/data_processor.py::_extract_resume_link`.
- Основная таблица owner `admin`, лист `Все лиды`.
- Источник: отклики и автоподбор Rabota.ru.

## Гипотеза

Старый fallback подставлял `/resume/<resume_id>`, когда в данных не хватало полного набора `resume_id`, `vacancy_id`, `response_id`.

## Проверка

11.08.2026 в основной таблице найдено 38 URL, точно совпадающих с `https://www.rabota.ru/resume/<id>`. Для проверенных строк БД не содержала пригодный `response_id` для восстановления точного response-URL.

## Наблюдение

Формировать `resume-search` с отсутствующим идентификатором нельзя: получилась бы ложная ссылка. До очистки создан серверный бэкап `/root/TrafficHub/data/backups/pending-resumes-before-canonical-fix-20260811T082108Z.json.gz`; затем очищены только 38 ошибочных ячеек. Повторная проверка: прямых URL — 0.

## Вывод

Канон Rabota.ru для выгрузки:

`https://www.rabota.ru/resume-search/<resume_id>/?source=response&vacancy_id=<vacancy_id>&response_id=<response_id>`

Код больше не использует fallback `/resume/<id>`. Если полного контекста отклика нет, ячейка остаётся пустой. Внешние URL резюме, в том числе PDF Zarplata.ru, не фильтруются.

## Следующий шаг

- Контролировать появление пустых `Резюме` как качество входных данных, а не подменять их неполной ссылкой.
- При необходимости восстановить данные только из исходного отклика Rabota.ru, где известны все три идентификатора.
