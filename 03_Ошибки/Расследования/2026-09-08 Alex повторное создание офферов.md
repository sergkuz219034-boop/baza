# Alex: повторное создание офферов

## Симптом

На 2026-09-08 API-конфиг Alex содержит семь записей: четыре Ozon, две Дикси, одну Я еда.

## Зона системы

`api/routers/offers.py:add_offer`, `dashboard/app.js:saveOffer`, owner-scoped `offer_mapping` в control store.

## Гипотеза

Повторные запросы сохранения дописывают оффер без проверки существования. Фронтенд не блокирует повторное нажатие. Конкретный источник повторных HTTP-запросов пока не доказан.

## Проверка

Сопоставлены live-конфиг Alex, runtime и серверный код. Четыре Ozon имеют одинаковые URL и пользовательские поля. Две Дикси имеют разные URL, лимиты 200/100 и разные привязки вакансий; автоматически объединять их нельзя.

## Наблюдение

`add_offer` безусловно выполняет append. `saveOffer` допускает конкурентные сохранения. Runtime router совпадает с repo по SHA-256. Main checkout имеет чужие незакоммиченные изменения; работа ведётся в отдельном server worktree.

## Вывод

Нужна идемпотентность повторного создания одинаковой записи и блокировка повторного сохранения формы. Название само по себе не является ключом дедупликации.

## Следующий шаг

Выбор между различающимися Дикси уточняется у пользователя; обе записи пока сохранены. Общий CI-дефект Leadsu остаётся отдельной задачей.
