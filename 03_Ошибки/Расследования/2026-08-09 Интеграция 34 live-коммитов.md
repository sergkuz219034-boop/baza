# Интеграция 34 live-коммитов

## Симптом

Production-ветка `/root/TrafficHub/main` расходилась с GitHub `main`: 34 коммита впереди и 20 позади. Простой reset потерял бы live-историю и восемь незакоммиченных файлов.

## Зона системы

Git history, production deploy, Docker runtime, Google Sheets, backfill, Telegram alerts.

## Гипотеза

Нужно объединить обе линии настоящим merge, а не cherry-pick только рабочих коммитов. Так сохраняются merge-решения и доказуемая принадлежность всех 34 коммитов новой канонической истории.

## Проверка

- `git rev-list --left-right --count origin/main...main`: `20 34`.
- Среди 34: 13 рабочих и 21 merge-коммит синхронизации со старым `origin/main`.
- Merge выполнен в отдельном worktree `/tmp/traffichub-integrate-live-34`.
- Кодовые файлы объединились автоматически; конфликты были только в `README.md` и `CHANGELOG.md`.
- `git merge-base --is-ancestor main HEAD` подтверждает включение всей live-ветки.
- Проверены Python compile, Bash syntax, Compose config и отсутствие runtime-ссылок Operator CRM.
- 87 целевых тестов прошли.

## Наблюдение

Merge-коммит `21c3f756f15063765776b44a28c2d2fcd13c1889` имеет родителей `c316e6231` и `89747e377`; он опубликован в GitHub `main`. Dirty live patch из восьми файлов чисто накладывается поверх нового дерева и сохранён отдельно до deploy.

Полный suite обнаружил независимую baseline-регрессию `tests/test_hr_agent_llm_first.py`: prompt длиной 6287 при контракте `<5000`. Исправление опубликовано коммитом `5b2a802611eb0f92c21e36e5fb35c8f1c3a4f813`; 58 HR Agent-тестов и все GitHub checks прошли.

Production развёрнут на `5b2a80261`. Runtime, worker, Account Manager и Content Bot собраны из чистого integration worktree; label `org.opencontainers.image.revision` у всех равен целевому SHA. Девять действующих сервисов healthy, `/api/health` вернул `status=ok`, Alembic находится на `0013_hr_agent_telegram_event_identity`. Автоматический пяти­минутный monitor завершился с `OK disk=56% inode=10% swap=8%`.

Восемь пользовательских live-изменений сохранены и восстановлены без изменения: SHA256 binary patch до/после `6936df9defa384e6367f95cca9efdc39b4a24868782dfe74cb3759b65b68ee3b`. Predeploy backup создан и проверен gzip.

Обнаружен deploy drift: production `.env` не задавал три GHCR image-переменные, а доступный GitHub token не имеет scope `read:packages`. Переменные исправлены. Текущий deploy выполнен из локально собранных immutable images; будущий pull-only deploy требует отдельный GHCR credential с `read:packages`.

## Вывод

Все 34 live-коммита вошли в канонический GitHub `main` без потери истории и применены в production. Код, контейнеры, миграции и monitor согласованы на SHA `5b2a80261`.

## Следующий шаг

- Выдать deploy credential минимальный scope `read:packages` для штатного pull из private GHCR.
- Отдельно проверить и оформить сохранённый dirty patch; не смешивать его с завершённой интеграцией.
