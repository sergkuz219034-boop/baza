# Резервные копии

## Подтверждённые backup contours

- system backups:
  - `repo_root/backups/traffichub-backup-*.zip`
- import backups:
  - `repo_root/data/backups/settings-import-backup-*.json`
  - `repo_root/data/backups/offers-import-backup-*.json`

## Что подтверждено кодом

- `api/routers/system.py`:
  - system backup root создаётся через `_backup_root()`
  - retention берётся из `TRAFFICHUB_BACKUP_KEEP`, default `5`
  - delete path валидирует имя `traffichub-backup-*.zip`
- `tests/test_system_backups.py`:
  - backup retention pruning реально покрыт тестом
  - delete backup требует admin
- import paths:
  - settings import создаёт `settings-import-backup-*`
  - offers import создаёт `offers-import-backup-*`

## Что важно

- старый `/root/TrafficHub_backup_archive` удалён как лишний архивный слой и не должен считаться active backup contour;
- system zip backup и import JSON backup — это разные operational механизмы;
- при cleanup важно фиксировать не только имя архива, но и к какому contour он относится: system backup, import backup или внешний manual archive.
