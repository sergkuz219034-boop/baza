# Стратегия

## Что проверять

- tenant isolation
- queue/job transitions
- auth/authz
- integrations
- runtime storage migration invariants
- что именно тест доказывает про код, и что он не доказывает про live backend

## Подтверждённые test contours

- `tests/test_worker_parallel.py`:
  - multi-owner parallel
  - parallel limit
  - targeted stop semantics
- `tests/test_ws_manager.py`:
  - log history snapshot
  - explicit snapshot
  - owner-scoped status delivery
- `tests/test_traffic_tenant_isolation.py`:
  - owner/tenant scope на router и DB layer
- `tests/test_traffic_auth_external.py`:
  - external auth
  - local cookie auth
  - bootstrap/logout flow
- `tests/test_integrations_sync.py`:
  - integrations normalization/import path
- `tests/test_runtime_logging.py`:
  - UI-relevant log filtering
- `tests/test_system_backups.py`, `tests/test_settings_import_export.py`, `tests/test_offers_import_export.py`:
  - backup/import-backup invariants

## Важная граница

- `sqlite` в тестах часто используется как быстрый isolated fixture;
- это не должно читаться как признак того, что production storage contract тоже SQLite-first;
- особенно это касается:
  - `tests/test_database.py`
  - `tests/test_leads_router.py`
  - `tests/test_traffic_hub_migrations.py`
  - `tests/test_traffic_tenant_isolation.py`
  - `tests/test_traffic_auth_external.py`
  - `tests/test_integrations_sync.py`
