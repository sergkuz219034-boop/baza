# Фронтенд

## Подтверждённый контур

- dashboard HTML/CSS/JS слой живёт рядом с backend web entrypoint;
- часть UI-состояния зависит от websocket и runtime bridge;
- `AccountManager` является отдельным product contour и его нельзя смешивать с основным dashboard.

## Что подтверждено по коду

- frontend entry files:
  - `dashboard/index.html`
  - `dashboard/app.js`
  - `dashboard/style.css`
- `dashboard/app.js` поднимает два разных websocket-канала:
  - `/ws/log`
  - `/ws/status`
- при разрыве `status` websocket UI переключается на polling каждые `5` секунд;
- `log` websocket при разрыве включает history fallback и reconnect;
- `AccountManager` открывается через token bootstrap из `/api/account-manager/token`, а не через прямой shared UI session.

## Log UI boundary

- `appendLog()` нормализует запись, классифицирует level и дедуплицирует обычные log lines;
- `spinner=true` рендерится как отдельная живая строка `.log-spinner`;
- обычный persistent log и transient/spinner поведение нельзя смешивать в одном объяснении бага;
- если проблема только в отображении realtime-лога, надо проверять `dashboard/app.js`, а не сразу storage/runtime.

## Что смотреть первым

1. `connectLogWs()` и `connectStatusWs()` в `dashboard/app.js`
2. token bootstrap для `AccountManager`
3. `appendLog()` / `normalizeLogEntry()` / spinner handling
4. расхождение между websocket-потоком, polling fallback и persisted history

## Operator UI invariant

- Единственная публичная operator-точка — корень поддомена `https://operator.traffic-hub.pro`; Caddy направляет его на внутренний backend route `/operator-host`, который отдаёт CRM-style shell из `dashboard/operator.html`.
- Старый публичный путь `https://traffic-hub.pro/operator` удалён и должен возвращать `404`.
- В operator shell нельзя возвращать тестовый ключ или тестовую авторизацию: форма вызывает боевой `POST /auth/operator-login`, а существующая сессия проверяется через `GET /auth/session`.
- Caddy направляет корень поддомена `operator.traffic-hub.pro` на `/operator-host`; DNS `A operator` должен указывать на live host до выпуска публичного TLS-сертификата.
- Канонический frontend поддомена — отдельный контейнер `operator_crm` (`operator_crm/index.html`, `operator_crm/app.js`, `operator_crm/styles.css`); встроенный `dashboard/operator.html` — legacy-шаблон и не является страницей, которую отдаёт Caddy.
- Operator shell остаётся отдельным UI-входом, но не отдельным контуром хранения данных: auth и данные обслуживаются TrafficHub API.
- Роль `operator` в `dashboard/app.js` является read/work-minimum режимом.
- Для `operator` скрываются user-level разделы `Офферы`, `Avito Import`, `Зарплата.ру`, `SuperJob`, `Аналитика`, `Настройки`, `TrafficHub CRM` и admin-only разделы.
- Если `operator` открывает запрещённый hash вручную, `switchTab()` возвращает его на `#leads`.
- Кнопки с `data-user-action` и `btn-stop` доступны только `user/admin`; `operator` не должен запускать полный цикл, выгрузку, рассылку или остановку job.
- Backend должен дублировать этот запрет через `require_user`, потому что UI-скрытие не является защитой.
- Общие правила интерфейса на всех operator-вкладках: заголовки используют `text-wrap: balance`, описание — `text-wrap: pretty`, интерактивные элементы имеют минимум `40px` по высоте, а нажатие кнопок — `scale(0.96)`. Переход вкладки анимирует смысловые блоки по очереди и отключается при `prefers-reduced-motion`.
- Первый учебный материал в `operator_crm` хранится как `training-material-01.pdf` и публикуется по стабильному URL `/training-material-01.pdf`; с 2026-07-15 его карточка называется «Краткая инструкция для рекрутера» и описывает Telegram-поиск и размещение вакансий.

## Encoding invariant

- Hardcoded пользовательский текст dashboard должен храниться только в UTF-8.
- Если в UI видны строки вида `Рџ...`, `Рћ...`, `вЂ...`, сначала проверять `dashboard/index.html` и `dashboard/app.js`, а не БД.
- Regression: `tests/test_dashboard_encoding.py` сканирует `dashboard/index.html` и `dashboard/app.js` на типовые mojibake markers.
- Fixed commit: `79c79dbab`.
- 2026-06-29 повторно подтверждено для `dashboard/app.js`, `AccountManager/dashboard/app.js`, `AccountManager/dashboard/index.html`: dirty-state может принести mojibake после ручных UI-правок, поэтому перед commit обязателен grep по `Р`, `вЂ`, `Ð`, `Ñ`.

## Auth token UI invariant

- Frontend не должен хранить bearer token в `localStorage/sessionStorage`.
- CI дополнительно запрещает прямой паттерн `headers.Authorization = ...` в restored TrafficHub SPA.
- Если нужно передать bearer header, использовать проверенный helper/pattern, который не нарушает `tests/test_traffic_embedded_auth.py`.
- Расследование: [[03_Ошибки/Расследования/2026-06-29 применение незакоммиченных изменений TrafficHub]]
