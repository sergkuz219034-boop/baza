## Подтверждённый контур

- dashboard HTML/CSS/JS слой живёт рядом с backend web entrypoint;
- часть UI-состояния зависит от websocket и runtime bridge;
- `AccountManager` является отдельным product contour и его нельзя смешивать с основным dashboard.

## Что подтверждено по коду

- frontend entry files:
  - `dashboard/index.html`
  - `dashboard/app.js`
  - `dashboard/style.css`
- `dashboard/app.js` поднимает два разных websocket-канала:
  - `/ws/log`
  - `/ws/status`
- при разрыве `status` websocket UI переключается на polling каждые `5` секунд;
- `log` websocket при разрыве включает history fallback и reconnect;
- `AccountManager` открывается через token bootstrap из `/api/account-manager/token`, а не через прямой shared UI session.

## Log UI boundary

- `appendLog()` нормализует запись, классифицирует level и дедуплицирует обычные log lines;
- `spinner=true` рендерится как отдельная живая строка `.log-spinner`;
- обычный persistent log и transient/spinner поведение нельзя смешивать в одном объяснении бага;
- если проблема только в отображении realtime-лога, надо проверять `dashboard/app.js`, а не сразу storage/runtime.

## Что смотреть первым

1. `connectLogWs()` и `connectStatusWs()` в `dashboard/app.js`
2. token bootstrap для `AccountManager`
3. `appendLog()` / `normalizeLogEntry()` / spinner handling
4. расхождение между websocket-потоком, polling fallback и persisted history
