# Оптимизация

## Что считать оптимизацией

- исправление owner-scoped hot paths;
- уменьшение рассинхрона между runtime stores;
- снижение стоимости чтения состояния для dashboard/API;
- явная проверка источника истины до оптимизации запроса.

## Практический анти-паттерн

- нельзя оптимизировать `SQLite path`, не проверив, активен ли он вообще на live;
- для текущего live-контура сначала считать активными PostgreSQL backend'и, а SQLite рассматривать как fallback/compatibility/test surface, пока не доказано обратное.
