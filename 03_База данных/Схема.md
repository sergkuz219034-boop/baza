# Схема

## Подтверждённый уровень

Полной ER-схемы внутри краткого канона нет. Есть подтверждённые runtime- и control-store инварианты.

## Что зафиксировано

- `users`
- `control_user_app_configs`
- `control_user_app_auth`
- `control_license_users`
- `tenant_memberships`
- `funnels`

## Что считать главным

- control/runtime слой уже нельзя описывать как один `control.db`;
- PostgreSQL-first контур подтверждён live;
- runtime fallback artifacts ещё встречаются, но не являются главным source of truth.

## Граница хранилищ

- active Autolead runtime state живёт в PostgreSQL-таблицах `autolead_*`;
- `autolead.db` остаётся как compatibility/fallback слой и не должен считаться основным production storage без прямого runtime-подтверждения;
- `control.db` относится к отдельному control-store/hybrid контуру и не равен runtime storage.

## Что уже в PostgreSQL runtime

- `autolead_app_log`
- `autolead_run_log`
- `autolead_send_history`
- `autolead_retry_queue`
- `autolead_leads`
- `autolead_autofit_seen`
- `autolead_invite_history`
- `autolead_invite_message_state`
- `autolead_control_sync_queue`

## Что ещё не надо путать с этой миграцией

- legacy SQLite fallback в `autolead.db`;
- `control.db` и его отдельный migration path;
- локальные test/maintenance paths, которые ещё умеют работать через SQLite.

## Остаточный SQLite surface

- `utils/database.py` держит routing/fallback ветки;
- `utils/runtime_store_schema.py` по-прежнему создаёт SQLite-таблицы совместимости;
- `utils/runtime_store_maintenance.py` обслуживает SQLite cleanup path;
- `services/stats_service.py` содержит SQLite branch для части postback-метрик, но на live `traffic_hub` product DB уже не SQLite;
- `utils/control_store.py` живёт отдельной жизнью и имеет собственный legacy import path.

## Короткая матрица факта

- `Autolead runtime`: active backend = PostgreSQL
- `traffic_hub` product DB: active backend = PostgreSQL
- `control_store`: active backend = PostgreSQL
- SQLite: compatibility/fallback/test surface, а не основной live backend
