# Воркеры

## Подтверждено

- контейнер: `traffichub_worker`;
- модель: subprocess-per-owner;
- stop/progress/state owner-scoped;
- heartbeat хранится в runtime-файле.

## Runtime contract

- busy: `queued`, `running`, `stopping`
- terminal: `idle`, `error`
- stop-path:
  - сначала `request_stop_for_job()`
  - затем event `job_stop_requested`
  - затем `SIGTERM`
  - затем `SIGKILL`, если subprocess не завершился
- stale busy state лечится после ~`6` часов
- default parallel owners на live: `2`

## Для дебага

- compare `/api/jobs/status`, Redis owner state, worker log, web websocket bridge;
- queued без прогресса почти всегда требует проверки `traffichub_worker`;
- restart worker во время активной job может порождать maintenance-ошибки, а не business error оффера.

## Практический playbook

1. Проверить `GET /api/health`.
2. Проверить контейнеры:
   - `autolead_server_bot`
   - `traffichub_worker`
   - `traffichub_redis`
   - `traffichub_postgres`
3. Проверить Redis keys:
   - `traffic_hub:jobs:queue`
   - `traffic_hub:jobs:state:<owner>`
   - `traffic_hub:jobs:active`
   - `traffic_hub:jobs:events`
4. Проверить `docker logs traffichub_worker`.
5. Проверить возраст `/app/data/runtime/worker.heartbeat`.

## Что считать нормой

- первый run даёт `queued`;
- повторный run при busy даёт `already_running`;
- stop почти сразу переводит owner в `stopping`;
- финальная задача уходит в `idle` или `error` с сохранением `last_command`.
