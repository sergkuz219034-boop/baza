# Сервисы и контейнеры

## Подтверждённый runtime-контур

Источник:

- live `docker-compose.yml` на `/root/TrafficHub`
- `docker ps` на сервере

| Сервис | Container | Назначение |
|---|---|---|
| web/API | `autolead_server_bot` | dashboard, `/api/*`, `/auth/*`, `/ws/*` |
| worker | `traffichub_worker` | owner-scoped job execution |
| PostgreSQL | `traffichub_postgres` | primary DB |
| Redis | `traffichub_redis` | queue, progress, stop flags, status bus |
| license auth | `traffichub_license_auth` | внешний auth-контур |
| license server | `traffichub_license_server` | license API |
| Account Manager | `traffichub_account_manager` | отдельное приложение на `am.traffic-hubcrm.ru` |
| Caddy | `traffichub_caddy` | TLS и reverse proxy |

## Что устарело

- описание “один backend-процесс и одна БД” устарело;
- описание “отдельная SPA `/traffic` как основной интерфейс” устарело;
- описание “всё живёт только в локальном workspace” устарело.

## Практический вывод

- web и worker нужно дебажить отдельно;
- job/runtime проблемы почти всегда требуют одновременно смотреть:
  - `autolead_server_bot`
  - `traffichub_worker`
  - Redis state
- auth/license/account-manager нельзя смешивать с core Autolead runtime в одну абстрактную “систему”.
