## Симптом

- В белой теме кнопки лог-панели (`Очистить`, `Скачать`, `Вниз`) визуально ломались.
- По скриншоту `Очистить` становилась почти черной при hover/active-состоянии.

## Зона системы

- `dashboard/style.css`
- toolbar лог-панели `.btn-sm`

## Гипотеза

- В стилях маленьких кнопок логов есть жестко прошитый dark background, который не зависит от theme variables.

## Проверка

- На live server в `dashboard/style.css` подтверждено:

```css
.btn-sm:hover { color: var(--text); background: #252523; border-color: var(--border-hi); transform: translateY(-1px); }
```

- Это правило theme-agnostic и в светлой теме рендерит темную заливку поверх светлой панели.

## Наблюдение

- Правило заменено на theme-aware вариант:

```css
.btn-sm:hover { color: var(--text); background: var(--surface-hover); border-color: var(--border-hi); transform: translateY(-1px); }
```

- После правки пересобран и перезапущен `autolead_server_bot`.

## Вывод

- Причина была не в самой белой теме целиком, а в одном жестко прошитом hover-цвете `#252523`.
- Лог-панель теперь использует переменные темы и не должна уходить в темную заливку в white mode.

## Следующий шаг

- При следующем аудите white theme проверить остальные hardcoded dark colors в `dashboard/style.css` по паттернам:
  - `#252523`
  - `rgba(0, 0, 0, ...)`
  - fixed dark backgrounds внутри button hover-state.
