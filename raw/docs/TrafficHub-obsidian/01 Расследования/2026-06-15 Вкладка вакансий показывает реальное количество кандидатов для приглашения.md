# Вкладка вакансий показывает реальное количество кандидатов для приглашения

## Симптом

Во вкладке вакансий UI показывал фиксированное значение кандидатов для приглашения и не отражал реальную доступную очередь текущего пользователя.

## Зона системы

- `api/routers/offers.py`
- `dashboard/app.js`
- runtime `RabotaRuClient.get_responses(...)`
- `invite_history`

## Гипотеза

UI использует hardcode вместо реального owner-scoped расчёта по откликам Rabota.ru за период с вычетом уже приглашённых кандидатов.

## Проверка

- inspected live `api/routers/offers.py`
- inspected live `dashboard/app.js`
- rebuilt `autolead_bot`
- вызвал `get_rabota_vacancies()` внутри live container для `admin`
- отдельно подтверждено, что правильный backend route вкладки вакансий — `GET /api/offers/vacancies`, а не `/api/vacancies`

## Наблюдение

- live backend теперь считает `invite_available` через `_collect_invitable_responses(...)`:
  - берёт `client.get_responses(period=30, include_invites=False)`
  - фильтрует по vacancy
  - дедуплицирует по `response_id`
  - исключает телефоны из `invite_history`
- live UI больше не использует hardcoded `5 кандидатов`:
  - показывает `invite_available`
  - `range.max` берётся из `invite_available`
  - `range.value` берётся из `invite_recommended`
  - если кандидатов нет, кнопка disabled и текст `Нет кандидатов`
- подтверждённый runtime-check внутри `autolead_server_bot` для `admin` на `2026-06-16`:
  - vacancy `54257329`
  - `invite_available=123`
  - `invite_recommended=5`
  - `invites=459`
  - `total vacancies=1`
- Значение `invite_available` не является константой и должно считаться заново на каждый запрос:
  - оно зависит от живых откликов Rabota.ru за период;
  - и от owner-scoped `invite_history`.

## Вывод

Количество кандидатов для приглашения во вкладке вакансий теперь должно быть owner-scoped и рассчитываться по живой очереди пользователя, а не по статическому frontend значению.
