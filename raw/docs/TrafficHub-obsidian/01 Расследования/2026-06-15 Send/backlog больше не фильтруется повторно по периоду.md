# 2026-06-15 Send/backlog больше не фильтруется повторно по периоду

## Симптом

- пользователь зафиксировал инвариант:
  - все лиды, уже попавшие в выгрузку/очередь, должны отрабатываться независимо от своей даты;
  - при этом обе Google Sheets таблицы должны оставаться отсортированными по колонке `Дата`.
- это исключает повторный date-filter на фазе `send`, если очередь уже сформирована.

## Зона системы

- `traffic_hub/services/job_runner.py`
- `services/leads_service.py`
- `modules/sheets_sync.py`

## Гипотеза

- проблема не в сортировке строк Google Sheets, а в том, что команда `send` и часть backlog-path в `full cycle` повторно фильтровали лиды по `period` внутри `run_sender()`.
- дополнительный скрытый дефект: диапазон строк `send_range_from/send_range_to` применялся как срез уже отфильтрованного списка, а не как реальные номера строк листа.
- дополнительный скрытый дефект: `load_pending_leads_for_send()` не исключал все строки с непустым `Статус`, а пропускал только небольшой legacy-набор статусов.

## Проверка

- подтверждено в `traffic_hub/services/job_runner.py`:
  - команда `send` грузила лиды через `load_leads_for_send(days=3650)`;
  - при включённых Google Sheets она вообще не брала очередь из `pending` листа;
  - затем вызывала `leads_service.run_sender(config, leads)` без `respect_period=False`;
  - это означало повторный фильтр по `Дата` внутри `run_sender()`.
- подтверждено в `services/leads_service.py`:
  - `run_sender()` имеет встроенный фильтр по периоду при `respect_period=True`;
  - в `run_full_cycle()` путь `pending Sheets` уже ставил `send_respect_period = False`;
  - но fallback-path `backlog из локальной БД` оставлял `send_respect_period = True`.
- подтверждено в `services/leads_service.py`:
  - блок `send_range_from/send_range_to` резал `leads[idx_from:idx_to]`;
  - для Google Sheets это неверно, потому что после исключения уже обработанных строк и других фильтров индекс списка перестаёт совпадать с номером строки листа.
- подтверждено в `modules/sheets_sync.py` до правки:
  - `load_pending_leads_for_send()` пропускал только статусы `отработан/processed/done`;
  - строки со статусами `Ошибка`, `Нет номера`, `Иностранный номер`, `Отправлено`, `Дубль` и другими прикладными значениями могли снова попадать в обычную очередь.
- одновременно подтверждено, что `modules/sheets_sync.py` должен продолжать сортировать `pending` и `processed` листы по колонке `Дата`.
- дополнительно выполнены live smoke-проверки на временных вкладках реальных Google Sheets:
  - сценарий `range 4–5`:
    - `loaded_fio = ["A", "C", "D"]`
    - `loaded_rows = [2, 4, 5]`
    - `ranged_fio = ["C", "D"]`
    - `ranged_rows = [4, 5]`
    - это подтверждает сразу два инварианта:
      - строка `B` со статусом `Ошибка` не попадает в очередь вообще;
      - диапазон строк режет очередь по реальным строкам листа, а не по индексу списка.
  - сценарий `range 3–5`:
    - `loaded_fio = ["A", "C", "D"]`
    - `loaded_rows = [2, 4, 5]`
    - `ranged_fio = ["C", "D"]`
    - `ranged_rows = [4, 5]`
    - это уже прямое подтверждение combined semantics:
      - даже внутри выбранного диапазона строк остаются только пустые `Статус`;
      - строка `B` с `Ошибка` не возвращается в очередь повторно.

## Наблюдение

- сортировка листа и фильтрация очереди по дате — это разные инварианты;
- user requirement:
  - в таблице строки должны быть упорядочены по `Дата`;
  - в отработке лид не должен пропадать из-за того, что его `Дата` уже вне текущего периода.
- strongest current runtime evidence:
  - команда queue-load из `pending` возвращает только пустые `Статус`;
  - range filter поверх этой очереди работает по `_sheet_row`;
  - эти два фильтра совместимы и не конфликтуют друг с другом.

## Вывод

- bug был не в Google Sheets order-path, а в runtime-path отработки backlog:
  - `send` повторно отсеивал часть уже накопленных лидов по `period`;
  - `full cycle` делал то же самое в fallback на локальный backlog без Sheets.
- отдельный bug был в семантике диапазона строк:
  - для Sheets он применялся к уже преобразованному списку лидов, а не к реальным строкам таблицы.
- отдельный bug был в queue selection:
  - обычная отработка не уважала правило `только пустой статус`, а переиспользовала часть строк с уже выставленными прикладными статусами.
- правильное поведение:
  - `scrape/upload` формируют и сортируют данные по `Дата`;
  - `send`/`backlog processing` отрабатывают уже накопленную очередь без повторного date-filter;
  - если задан диапазон строк, для Sheets он применяется по `_sheet_row`, то есть по реальному номеру строки листа `pending`;
  - в саму очередь попадают только строки с пустым `Статус`.

## Следующий шаг

- дальнейшие расследования по этой теме нужны только при новых live-regressions;
- на 2026-06-15 базовый runtime-инвариант по `send/backlog/range/status` считается подтверждённым.
