# Контейнеры и сервисы

## Подтверждённый runtime-контур

Источник:

- live `docker-compose.yml` на `/root/TrafficHub`, прочитан по SSH `2026-06-11`;
- `docker ps` на сервере `2026-06-15`;
- локальный bundle как fallback/offline copy.

| Сервис | Container | Назначение | Чем подтверждено |
|---|---|---|---|
| Autolead web | `autolead_server_bot` | Dashboard, `/api/*`, `/auth/*`, `/ws/*` | live compose + live `api/server.py` |
| Worker | `traffichub_worker` | Исполнение queued jobs | live compose + live `traffic_hub/worker.py` |
| PostgreSQL | `traffichub_postgres` | Основная server DB | live compose |
| Redis | `traffichub_redis` | Queue, job state, progress, stop flags | live compose + live `traffic_hub/services/job_queue.py` |
| License auth | `traffichub_license_auth` | Внешний auth-контур на `8400` | live compose |
| License server | `traffichub_license_server` | License API, читает PostgreSQL через `POSTGRES_HOST=traffichub_postgres` | live compose + `license_server/app.py` |
| Account Manager | `traffichub_account_manager` | Отдельный backend на `8000`, мостится из TrafficHub через `/api/account-manager/token` | live compose + live `api/server.py` |
| Caddy | `traffichub_caddy` | HTTPS reverse proxy для публичных доменов | live compose |

## Host containers вне TrafficHub compose

На host также видны контейнеры, не относящиеся к этому compose-проекту:

- `searxng-local`
- `amnezia-xray`
- `mfo_api`

Что важно:

- их нельзя автоматически считать частью TrafServer / TrafficHub;
- `laughing_diffie` со статусом `Created` похож на orphan/manual leftover, а не на штатный сервис проекта.

## Критичные зависимости

- `autolead_server_bot` зависит от:
  - PostgreSQL через `DATABASE_URL=postgresql+asyncpg://...@postgres:5432/traffichub`
  - Redis через `REDIS_URL=redis://redis:6379/0`
  - Account Manager через `ACCOUNT_MANAGER_BASE_URL=http://account_manager:8000`
- `traffichub_worker` зависит от:
  - PostgreSQL
  - Redis
  - runtime volumes `/app/data/runtime/*`
- `traffichub_license_server` зависит от `traffichub_postgres` через `POSTGRES_HOST`.
- `traffichub_caddy` зависит по health от:
  - `autolead_bot`
  - `license_auth`
  - `license_server`
  - `account_manager`

## Health / runtime mechanics

- `autolead_server_bot` health:
  - `curl -sf http://localhost:8080/api/health`
- `traffichub_worker` health:
  - heartbeat file `/app/data/runtime/worker.heartbeat`
  - контейнер healthy, если heartbeat моложе `180` секунд
- `traffichub_postgres` health:
  - `pg_isready -U traffichub -d traffichub`
- `traffichub_redis` health:
  - `redis-cli ping`

## Риск

- Старые документы всё ещё могут описывать one-process режим без worker и Redis.

## Параллельный дебаг несколькими разработчиками

### Безопасное разделение по контейнерам

- Разработчик A:
  - `autolead_server_bot`
  - HTTP/API, session/auth, dashboard, `/ws/*`
- Разработчик B:
  - `traffichub_worker`
  - queue execution, owner jobs, worker logs, subprocess/runtime
- Разработчик C:
  - `traffichub_postgres` и `traffichub_redis`
  - только read-only inspect, health, state, keys, queries
- Разработчик D:
  - `traffichub_license_auth`, `traffichub_license_server`, `traffichub_account_manager`
  - auth/license/account bridge
- Разработчик E:
  - `traffichub_caddy`
  - edge routing, TLS, upstream binding

### Что нельзя делать одновременно без координации

- Не запускать smoke на одних и тех же owner'ах.
- Не перезапускать `autolead_server_bot` и `traffichub_worker` независимо, если другой разработчик проверяет долгую job.
- Не менять `docker-compose.yml`, `.env`, runtime secrets и feature flags без синхронизации по времени применения.
- Не делать write-операции в PostgreSQL/Redis “для удобства”, пока другой разработчик пытается воспроизвести баг.

### Правило для jobs/debug

- Для всех live smoke использовать только debug-owner'ов.
- После расследования `2026-06-14` актуальная worker-модель:
  - multi-owner parallel разрешён;
  - safe default на production host: `WORKER_MAX_PARALLEL_OWNERS=2`
- Следовательно одновременно безопасно:
  - максимум `2` активных debug-owner job;
  - остальные разработчики работают через read-only inspect/logs/API, не создавая новые `run`.

### Практическая схема

- Один разработчик держит `docker logs -f autolead_server_bot`
- Второй держит `docker logs -f traffichub_worker`
- Третий смотрит:
  - PostgreSQL runtime facts
  - Redis keys `traffic_hub:jobs:*`
- Четвёртый проверяет edge/auth:
  - `traffichub_caddy`
  - `traffichub_license_auth`
  - `traffichub_license_server`
  - `traffichub_account_manager`

### Если нужен общий live incident room

- Фиксировать:
  - кто владеет каким контейнером;
  - кто имеет право на restart;
  - какие debug-owner'ы заняты;
  - какой контейнер сейчас “read-only”, а какой допускает активные проверки.
