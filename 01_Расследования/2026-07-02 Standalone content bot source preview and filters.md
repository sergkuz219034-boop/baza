# 2026-07-02 Standalone content bot source preview and filters

## Симптом

- После перевода `Telethon`-источников на модель `dialogs` список в `content bot` оставался слишком грубым:
  - mixed `чаты + каналы` без фильтра;
  - выбор источника сразу запускал генерацию;
  - пользователь не видел preview последних сообщений перед созданием черновика.

## Зона системы

- live repo: `/root/TrafficHub`
- service: `standalone_content_bot`
- code: `/root/TrafficHub/standalone_content_bot/app.py`

## Гипотеза

- runtime-данных из `Account Manager` уже достаточно;
- проблема находится не в backend интеграции, а в Telegram UX слоя `Источники`.

## Проверка

- Проверен live `app.py`:
  - `list_source_channels()` и `list_source_messages()` уже возвращают нужные данные;
  - до фикса сценарий был `аккаунт -> источник -> сразу генерация`.
- В live добавлены:
  - фильтры `🧾 Все`, `💬 Чаты`, `📣 Каналы`;
  - preview screen с последними сообщениями источника;
  - отдельный шаг подтверждения `✨ Сгенерировать`;
  - корректный `↩️ Назад` из preview обратно в список источников с сохранённым фильтром.
- Runtime smoke внутри `traffichub_standalone_content_bot`:
  - `render_source_channels(-1, 'chat')` вернул текст с фильтром `чаты` и `14 из 18` доступных dialogs у `Виктория`;
  - `render_source_messages_preview(...)` сформировал preview-блок с типом источника, названием, `chat_id` и последними сообщениями;
  - helper-фильтр подтвердил split:
    - `chat_count = 14`
    - `channel_count = 4`

## Наблюдение

- Root issue был UX-level:
  - пользователь выбирал источник вслепую;
  - не мог быстро сузить список только до чатов или только до каналов;
  - не видел материал, по которому бот будет собирать новый пост.
- После фикса сценарий стал:
  - `аккаунт -> фильтр -> источник -> preview -> генерация`.

## Вывод

- `content bot` стал ближе к логичной работе с `Telethon`-источниками:
  - сначала выбор нужного класса источников;
  - затем проверка свежего контекста;
  - только потом генерация черновика.
- Это уменьшает случайные промахи по источнику и делает flow проверяемым вручную прямо в Telegram.

## Следующий шаг

- Если понадобится усиление:
  - добавить paging по источникам, если `dialogs > 20`;
  - дать отдельный toggle `только каналы с комментариями`, когда в live появятся `has_comments=true`;
  - добавить ручной выбор количества сообщений для preview/generation.
