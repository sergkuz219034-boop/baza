# LLM Wiki — Schema (CLAUDE.md)

Ты — хранитель этой wiki. Твоя задача: читать источники, извлекать знания, обновлять страницы, поддерживать перекрёстные ссылки. Ты никогда не редактируешь `raw/` — только читаешь оттуда. Все правки — только в `wiki/`.

---

## Структура директорий

```
llm-wiki/
├── CLAUDE.md          ← этот файл (правила и схема)
├── raw/               ← источники (ТОЛЬКО ЧТЕНИЕ — не изменять!)
│   └── assets/        ← изображения из источников
├── wiki/              ← всё, что пишет LLM
│   ├── index.md       ← каталог всех страниц
│   ├── log.md         ← хронологический лог операций
│   ├── overview.md    ← обзорная страница / точка входа
│   ├── concepts/      ← страницы концепций
│   ├── entities/      ← страницы персон, инструментов, проектов
│   ├── sources/       ← краткие резюме источников
│   └── synthesis/     ← анализы, сравнения, выводы
```

---

## Правила работы

### Формат каждой страницы wiki
Каждый файл в `wiki/` должен иметь YAML-frontmatter:

```yaml
---
title: "Название страницы"
type: concept | entity | source | synthesis | overview
tags: [тег1, тег2]
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: [filename1.md, filename2.md]
---
```

### Внутренние ссылки
Используй формат `[[путь/к/файлу|Название ссылки]]` — всегда с явным путём, чтобы избежать ghost-ссылок в Obsidian.

Пример: `[[concepts/architecture|Архитектура системы]]`

### Операция: Ingest (добавление источника)
1. Прочитай источник из `raw/`
2. Обсуди с пользователем ключевые выводы
3. Создай резюме в `wiki/sources/` 
4. Обнови или создай страницы концепций в `wiki/concepts/`
5. Обнови `wiki/index.md` — добавь новые страницы
6. Добавь запись в `wiki/log.md` с форматом: `## [YYYY-MM-DD] ingest | Название источника`
7. Один источник может затронуть 5–15 страниц — это нормально

### Операция: Query (вопрос к wiki)
1. Прочитай `wiki/index.md` — найди релевантные страницы
2. Прочитай найденные страницы
3. Синтезируй ответ со ссылками на страницы
4. Если ответ ценный — сохрани его как новую страницу в `wiki/synthesis/`

### Операция: Lint (проверка здоровья wiki)
Проверь:
- Страницы без входящих ссылок (orphans)
- Противоречия между страницами
- Устаревшие утверждения
- Концепции, упомянутые, но без своей страницы
- Сломанные wikilinks
Добавь запись в лог: `## [YYYY-MM-DD] lint | краткий результат`

---

## Размеры и лимиты
- `wiki/log.md`: записи старше 30 дней сжимай до одной строки в неделю
- `wiki/index.md`: не более 200 строк — группируй по категориям
- Любая страница: если превышает 400 строк — раздели на несколько
- Весь `wiki/` на проекте: ориентир ~300 строк (не жёсткий лимит)

---

## Соглашения по тегам
- `#concept` — абстрактная концепция, паттерн, идея
- `#entity` — персона, инструмент, проект, компания
- `#source` — резюме источника
- `#synthesis` — анализ, сравнение, вывод
- `#hub` — Map of Content (MOC), объединяет 3+ связанных страниц

---

## Важные подсказки
- Obsidian Graph View показывает структуру связей — поддерживай её чистой
- Источники (`raw/`) — источник истины, wiki — компиляция
- Полезные ответы на вопросы **сохраняй** обратно в wiki — знания должны накапливаться
- При противоречии между источниками — создай страницу в `wiki/synthesis/` с разбором
