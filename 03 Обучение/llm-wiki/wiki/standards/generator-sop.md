# 🤖 SOP: Генератор вакансий

Этот протокол является **обязательным** для исполнения LLM при получении задачи на написание или редактирование вакансии.

## ⚖️ Иерархия принятия решений (Decision Hierarchy)

При генерации текста LLM обязана соблюдать следующие приоритеты:

1.  **БАН-ФИЛЬТР (Compliance First)**: 
    - Проверка на соответствие [[standards/compliance-rules|правилам модерации Rabota.ru]].
    - Нет ссылок, нет слов «ГПХ», «Самозанятость», нет CAPS.
    - Уникальность лида (первые 150 знаков) — 100%.
    - **Если есть нарушение — текст переписывается до полного устранения.**

2.  **ПРОДАЖА (Conversion Second)**: 
    - Применение принципов из [[synthesis/global-copywriting-knowledge-base|Глобальной базы знаний]] (боли, выгоды, CTA).
    - Текст должен конвертировать холодный трафик (Stage 1-2) в отклик.

3.  **СТИЛЬ (Aesthetics Third)**: 
    - «Живой» текст: ритмика (Кларк), микро-детали (Сургай).

> [!IMPORTANT]
> **Приоритет результата**: Если академический принцип из книг (Шварц, Кларк и др.) делает текст слишком сложным для массового подбора (курьеры, водители, склад) — **игнорируй его**. Наша цель — максимальное количество лидов, а не литературная безупречность.

## ⚡ Экспресс-алгоритм (7 шагов)

### Шаг 1. Анализ Рынка и Архива
- Уточнить: Должность, Город, Ключевые выгоды.
- Определить **[[standards/writing-principles#интенсивность-рынка-market-sophistication|интенсивность-рынка]]** (Stage 1-5). Если рынок перегрет (курьеры, склад) — использовать **Новый механизм**.
- Определить **[[standards/writing-principles#уровни-осведомленности-awareness-levels|уровень-осведомленности]]** (Stage 1-5).
- Прочесть **[[history/vacancy-archive|📦 Архив вакансий]]** — выбрать уникальную комбинацию: Структура + Тон.

### Шаг 1.5. Проверка семантики (Wordstat)
- Убедиться, что название должности — самое «ходовое» в поиске.
- **Выбор «Золотого заголовка»**: Использовать слова, которые люди реально вбивают (например, «Разнорабочий» может быть популярнее, чем «Подсобный рабочий»).

### Шаг 2. Заголовок (Title) — Цель: CTR (Клик)
- **Только должность.** Без зарплат и бонусов.
- Максимум одно уточнение в скобках: `(м. Ховрино)` или `(график 2/2)`.
- Должен цеплять через релевантность поисковому запросу.

### Шаг 3. Ударный Лид (Первые 150 знаков) — Цель: CTR + Захват внимания
- Должен быть на 100% уникален.
- **Точка входа**: Нарратив, Факт или Вопрос. Цепляет боль или желание аудитории (Stage 1-2).
- Будь краток и ярок. Каждое слово либо продает, либо фильтрует.

### Шаг 4. Сборка Тела — Цель: Удержание и Убеждение
- **Принцип**: Прозрачность и Факты. Никакой "красоты" ради красоты.
- Каждое условие — это [[concepts/faktoid|Фактоид]]. Каждое преимущество — [[standards/writing-principles#язык-выгоды|Язык выгоды]].
- **Структура А (Стандарт)**: Лид → Обязанности → Условия → Требования → CTA.
- **Структура Б (Инверсия)**: Лид → Деньги/Выгоды → Обязанности → Требования → CTA.
- **Структура В (Нарратив)**: История/Кейс → Суть работы → Плюшки → Требования → CTA.

### Шаг 4.5. CTA (Призыв к действию) — Цель: Действие (Отклик)
- Должен быть ОДНИМ, четким и максимально легким для выполнения.
- Пример: "Нажмите 'Откликнуться', мы перезвоним в течение часа".

### Шаг 5. Тональность и Анти-ИИ
- Тон: деловой, дружелюбный (B2C). Никакой агрессии.
- Применить **[[standards/writing-principles#4-продвинутое-анти-палево-сургай|Продвинутое "Анти-палево"]]**:
    - [ ] Разная длина абзацев и предложений.
    - [ ] Минимум один "неудобный" микро-факт (минус/сложность).
    - [ ] Смешанное форматирование списков.

### Шаг 6. Финальная проверка (LINT)
- [ ] Нет ссылок на внешние ресурсы.
- [ ] Нет ГПХ/Самозанятости в тексте.
- [ ] Нет дискриминации (пол, возраст).
- [ ] Жирный шрифт < 30%.
- [ ] Удален весь [[concepts/kantselyarit|канцелярит]].

### Шаг 7. Обновление Архива и Журнала ошибок
- Добавить запись в таблицу в **[[history/vacancy-archive|Архиве вакансий]]**.
- **Анализ неудач**: Если была ошибка (бан, плохая конверсия), добавь кейс в [[synthesis/global-copywriting-knowledge-base#🧪-часть-7-запрещенные-паттерны|Часть 7 (Запрещенка)]].
- **Перед генерацией следующей вакансии**: Проанализировать журнал ошибок и запрещенные паттерны.
