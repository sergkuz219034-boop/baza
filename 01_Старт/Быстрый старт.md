# Быстрый старт

## Маршрут для нового разработчика

1. Прочитать [[00_Главная/Обзор проекта|Обзор проекта]].
2. Открыть [[01_Старт/Структура репозитория|Структура репозитория]].
3. Пройти [[02_Архитектура/Обзор системы|Обзор системы]] и [[02_Архитектура/API|API]].
4. Для runtime-layer открыть [[05_Эксплуатация/Конфигурация|Конфигурация]] и [[05_Эксплуатация/Воркеры и расписание|Воркеры и расписание]].
5. Для first-debug использовать [[06_Отладка/Рецепт отладки|Рецепт отладки]].

## Канонические входы

- live source repo: `/root/TrafficHub`
- wiki: этот vault
- imported engineering archive: [[материалы/документы/TrafficHub-obsidian/README|TrafficHub-obsidian]]

## Минимальный onboarding flow

1. Понять карту системы по [[02_Архитектура/Обзор системы|Обзору системы]].
2. Зафиксировать реальные точки входа по [[04_Код/Бэкенд|Бэкенду]] и [[04_Код/Инфраструктура|Инфраструктуре]].
3. Сверить runtime-маркеры в [[05_Эксплуатация/Конфигурация|Конфигурации]].
4. Для любой живой проблемы идти через [[06_Отладка/Рецепт отладки|Рецепт отладки]], а не через случайный grep по vault.

## Чего не делать

- не воспринимать `baza` как source repo приложения;
- не менять канон на основе неподтверждённой старой заметки;
- не описывать систему как single-db/single-process, если live runtime показывает другое.
