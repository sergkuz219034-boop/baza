# Известные проблемы

## Для vault

- legacy-структура слишком смешивает проект, обучение, диалоги и архив;
- project-context пока размазан по нескольким корням.

## Для TrafficHub

- краткий список проблем здесь не каноничен;
- source of truth по инцидентам и runtime-багам живёт во внешней инженерной wiki.

## Канонические bug-классы для этой базы

- queue/status/UI mismatch;
- stale busy state и stop lag;
- worker restart во время активной job;
- owner-scoped конфиги, ломающие proxy/sheets/retry;
- расхождение live-кода между web container и worker container.

## Что проверять первым по каждому классу

- queue/status/UI mismatch:
  - `/api/jobs/status`
  - Redis `traffic_hub:jobs:state:<owner>`
  - websocket/status bridge
- stale busy state и stop lag:
  - `traffic_hub/services/job_queue.py`
  - worker log
  - stop events и owner subprocess shutdown
- worker restart во время активной job:
  - container restart history
  - owner state до/после
  - `Worker restarted before job finished`
- owner-scoped config bugs:
  - `control_user_app_configs`
  - `control_user_app_auth`
  - user-specific `google_sheets.*`
  - user-specific `rabota_ru.proxy_url`
- image drift:
  - код внутри `autolead_server_bot`
  - код внутри `traffichub_worker`
  - нельзя считать web container единственным доказательством фикса

## Норма для triage

Если проблема выглядит как «ничего не работает», сначала проверять worker/Redis/runtime state, а не офферы, вакансии или UI-текст ошибок.
