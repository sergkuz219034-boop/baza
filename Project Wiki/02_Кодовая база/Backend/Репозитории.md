# Репозитории

## Канон

- локальный `baza` не является source repo приложения;
- server-side mutable repo находится в `/root/TrafficHub`;
- `baza` хранит только knowledge-layer и ссылки на source of truth.

## Следствие

- любые выводы про backend-репозитории нужно подтверждать live-кодом на сервере, а не только заметками vault.

## Runtime repository boundary

- legacy operational SQLite читается через `utils/database.py`;
- поверх него уже введён boundary `utils/runtime_repository.py`;
- это важный переходный слой между старым storage и новым `traffic_hub` API/CRM контуром.

## Что уже разложено по отдельным store-фасадам

- `utils/runtime_store_logs.py`
- `utils/runtime_store_delivery.py`
- `utils/runtime_store_invites.py`
- `utils/runtime_store_control_sync.py`
- `utils/runtime_store_leads.py`
- `utils/runtime_store_autofit.py`
- `utils/runtime_store_maintenance.py`
- `utils/runtime_store_schema.py`

## Почему это важно

- `utils/database.py` больше нельзя считать единственным каноническим storage-layer;
- repository boundary уже используется для owner-scoped read/export/reset path;
- новые расследования про runtime storage нужно привязывать к конкретному store-модулю, а не к абстрактной "базе".
