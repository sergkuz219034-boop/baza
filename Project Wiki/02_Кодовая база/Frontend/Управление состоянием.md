# Управление состоянием

## Подтверждённый runtime state

- job state и progress идут через Redis;
- UI получает public status/log bridge через web/API слой;
- stop/status/log контур owner-scoped.

## Основные каналы состояния

- `traffic_hub:jobs:state:<owner>`
- `traffic_hub:jobs:progress:<owner>`
- `traffic_hub:jobs:stop:<owner>`
- `traffic_hub:jobs:events`

## Следствие для разработки

- нельзя объяснять UI state только локальным frontend-кодом;
- источник рассинхрона может быть в worker, Redis, websocket bridge или frontend mapping;
- debugging owner A ничего не доказывает про owner B.
