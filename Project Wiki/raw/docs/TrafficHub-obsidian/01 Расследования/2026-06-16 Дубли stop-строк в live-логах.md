# 2026-06-16 Дубли stop-строк в live-логах

## Симптом

В UI лога после остановки задачи отображались две соседние строки:

- `Полный цикл остановка`
- `Полный цикл остановлен`

Визуально это выглядело как дубль одного действия.

## Зона системы

- `api/server.py::_relay_job_event()`
- `dashboard/app.js::syncRealtimeJobSpinner()`
- `dashboard/app.js::appendLog()`
- Redis job events `job_stop_requested` и `job_stop`

## Гипотеза

`job_stop_requested` нужен как realtime-состояние, но frontend показывал его как обычную строку лога. Когда позже приходил terminal event `job_stop`, spinner-строка `остановка` не заменялась, а оставалась рядом с итоговой строкой `остановлен`.

## Проверка

По live source:

- `api/server.py` формирует `job_stop_requested -> "[⛔] {command}: остановка"`;
- `api/server.py` формирует `job_stop -> "[⛔] {command}: остановлен"`;
- `dashboard/app.js` создавал spinner-строку для `status=stopping`;
- `appendLog()` вставлял обычную terminal-строку рядом со spinner, не удаляя его.

## Наблюдение

Добавлено frontend-правило `isTerminalStopLog(entry)`: если приходит финальный stop-log, существующая `.log-spinner` строка удаляется перед вставкой terminal-строки. Внутренние job events не менялись.

## Вывод

Дубль был UI-эффектом, а не повторным stop-событием backend. Каноническое поведение: во время остановки можно показывать временную spinner-строку, но после terminal stop в логе остаётся только итоговая строка `остановлен`.

## Следующий шаг

- При следующем rebuild `autolead_bot` source уже содержит правку.
- После пользовательской проверки убедиться, что остановка больше не оставляет две строки рядом.
