# 2026-06-16 Аудит и унификация локальных wiki на ПК

## Симптом

- на ПК одновременно присутствовало несколько wiki/vault:
  - `wiki/TrafficHub-obsidian`
  - `wiki/Baza-obsidian`
  - `.tmp_git/Wiki_Obsidian`
  - `TrafServer_Wiki_Debug_Dev_2026-06-09`
- часть из них была в разных форматах;
- старые локальные заметки уже расходились с live GitHub и текущим server-контуром.

## Зона системы

- локальная документация;
- GitHub wiki-репозитории;
- Obsidian vault structure.

## Гипотеза

Нужен единый базовый формат:

- `README`
- `START_HERE`
- `Index`
- проектный блок `01 Проекты/...`

При этом:

- `TrafficHub-obsidian` должен оставаться полной инженерной картой;
- `Baza-obsidian` и `Wiki_Obsidian` должны оставаться более краткими внешними слоями;
- старый debug-vault нужно явно пометить как архивный.

## Проверка

Подтверждено локально `2026-06-16`:

- `Wiki_Obsidian` существовал как git repo, но только на ветке `master` и в плоском legacy формате;
- `baza` существовал как git repo на `main` и уже имел новый каркас;
- `TrafServer_Wiki_Debug_Dev_2026-06-09` не имел даже root `Index.md` и выглядел как старый snapshot без явной пометки архивности.

## Наблюдение

- `baza` обновлён и pushed в `main`;
- `Wiki_Obsidian` приведён к общему каркасу и pushed в новую ветку `main`;
- старый debug-vault получил `README`, `START_HERE`, `Index` с явной пометкой, что он архивный;
- локальный `wiki/README.md`, `wiki/START_HERE.md`, `wiki/baza-README.md` обновлены под новый реальный sync-статус.

## Вывод

- на текущем ПК канонический порядок такой:
  - `wiki/TrafficHub-obsidian` — полная инженерная карта
  - `wiki/Baza-obsidian` — локальное зеркало краткой внешней базы
  - `Wiki_Obsidian` GitHub repo — внешний Obsidian-слой, приведён к тому же каркасу
  - `TrafServer_Wiki_Debug_Dev_2026-06-09` — только архивный snapshot

## Следующий шаг

- при дальнейших изменениях сначала обновлять `TrafficHub-obsidian`;
- затем переносить короткий подтверждённый слой в `Baza-obsidian` и `Wiki_Obsidian`;
- legacy snapshot больше не развивать.
