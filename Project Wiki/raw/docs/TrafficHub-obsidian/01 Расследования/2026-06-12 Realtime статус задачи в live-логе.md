# 2026-06-12 Realtime статус задачи в live-логе

## Симптом

- пользователь просил вернуть старый органичный вид логов:
  - короткие русские строки;
  - время;
  - realtime-статусы работы;
  - без технического мусора и лишних counters в heartbeat;
- текущий live-log содержал либо шумные технические строки, либо сухой текст без аккуратного UI-ритма.

## Зона системы

- `api/server.py`
- `api/ws_manager.py`
- `traffic_hub/services/job_queue.py`
- `utils/runtime_logging.py`

## Гипотеза

- realtime-статусы уже шли из `job_queue`, но:
  - heartbeat-строки были слишком техническими;
  - UI рендерил лог как простой монотонный текстовый список;
  - часть агрегатного шума (`run_full_cycle: итог:` и подобные строки) продолжала попадать в timeline.

## Проверка

- подтверждено по live-коду:
  - `traffic_hub/services/job_queue.py` публикует `job_queued`, `job_start`, `job_stop_requested`, `job_stop`, `job_done`, `job_error`;
  - `api/server.py` конвертирует их в owner-scoped log payload;
  - `dashboard/app.js` фильтрует и рендерит строки log timeline;
  - `utils/runtime_logging.py` решает, какие backend-строки вообще допустимы в UI.
- на live server выполнена правка:
  - `api/server.py`
    - heartbeat остаётся realtime, но текст упрощён до `Выгрузка выполняется`, `Рассылка выполняется`, `Полный цикл выполняется`;
    - `job_stop` и `job_done` больше не показывают progress-счётчики в status-строке;
    - heartbeat отправляется как `spinner=true`, чтобы обновлять одну живую строку, а не плодить шум;
  - `dashboard/app.js`
    - время ужато до `HH:MM:SS`;
    - текст очищается от технических префиксов `[i]`, `[OK]`, `[⛔]`, `ERROR:`;
    - строки рендерятся как аккуратная лента `время -> маркер -> сообщение`;
    - скачивание логов теперь использует очищенный пользовательский текст;
  - `dashboard/style.css`
    - log timeline получил нормальную разметку и маркеры статуса;
  - `utils/runtime_logging.py`
    - добавлен drop для `run_full_cycle: итог:`.

## Наблюдение

- статусные строки идут в реальном времени через тот же owner-scoped live-log;
- пока задача выполняется, heartbeat обновляет одну живую строку вместо добавления дублей;
- формат стал коротким и user-facing:
  - `21:34:05  Полный цикл в очереди`
  - `21:34:06  Полный цикл запущен`
  - `21:34:21  Полный цикл выполняется`
  - `21:40:03  Полный цикл завершён`
- для ошибок остаётся красный статус и русский текст;
- старые counters `(..., ошибок: ...)` убраны именно из status-line, но детальные прикладные сообщения офферов и ошибок остаются в логе.

## Вывод

- log timeline снова стал похож на старый рабочий формат:
  - живой;
  - компактный;
  - на русском;
  - с временем;
  - без технического мусора в основной ленте.
- realtime-статус виден и по pill, и по самой лог-ленте, без ощущения `ничего не происходит`.

## Следующий шаг

- если понадобится ещё сильнее ужать timeline, следующий слой очистки:
  - сгруппировать одинаковые success-строки офферов за короткий интервал;
  - отдельно пометить partner-disabled кейсы вроде `disabled.html` как прикладные статусы, а не просто error text.
