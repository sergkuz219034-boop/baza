# 2026-06-12 Фон входа и регистрации

## Симптом

- экран входа визуально отличался по фону от экрана регистрации;
- пользователь попросил сделать фон входа таким же, как фон регистрации.

## Зона системы

- `dashboard/style.css`
- `dashboard/index.html`
- `api/server.py`

## Гипотеза

- вход и регистрация рендерятся из разных источников;
- у них разные CSS-источники фона:
  - login: `dashboard/style.css`
  - register: `_REGISTER_SHARED_STYLE` в `api/server.py`
- расхождение вызвано не карточкой формы, а fullscreen background слоями.

## Проверка

- на сервере подтверждено:
  - экран входа использовал `#login-overlay` с фоном `rgba(9, 9, 8, 0.88)`;
  - экран регистрации использовал:
    - `radial-gradient(circle at top left, rgba(94, 179, 61, 0.10), transparent 28%)`
    - `radial-gradient(circle at bottom right, rgba(122, 185, 255, 0.10), transparent 24%)`
    - базовый цвет `#121212`
    - grid overlay через `body::after`.
- в `dashboard/style.css` фон login-overlay приведён к тому же набору слоёв, что и у регистрации;
- добавлен `#login-overlay::after` с тем же grid-рисунком;
- пересобран и перезапущен `autolead_server_bot`;
- runtime-проверка внутри контейнера подтвердила наличие нового CSS в `/app/dashboard/style.css`.

## Наблюдение

- проблема была только в визуальном слое `login-overlay`;
- общий dashboard после логина не затронут;
- менять `body` целиком не потребовалось, поэтому рабочий интерфейс не изменился.

## Вывод

- фон входа и регистрации были разведены по двум разным шаблонам;
- теперь login screen повторяет фон registration screen на уровне overlay CSS;
- изменение локализовано и не влияет на app-shell после авторизации.

## Следующий шаг

- если позже потребуется полное визуальное выравнивание auth-flow, стоит вынести login/register background в один shared CSS source вместо дублирования в `dashboard/style.css` и `api/server.py`.
