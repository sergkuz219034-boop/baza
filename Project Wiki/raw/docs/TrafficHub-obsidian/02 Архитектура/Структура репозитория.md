# Структура репозитория

## Кратко

TrafficHub — не один backend и не один storage-контур.

Подтверждённые слои:

- legacy Autolead runtime:
  - `api/`
  - `services/`
  - `modules/`
  - `utils/`
  - `dashboard/`
- новый `traffic_hub` слой:
  - PostgreSQL
  - Alembic
  - Redis queue/state
  - worker
- отдельный `AccountManager`
- отдельный `license_auth` / `license_server`

## Почему это важно

Любой инцидент сначала нужно привязать к контуру:

- UI/dashboard;
- legacy Autolead runtime;
- `traffic_hub`;
- control/auth plane;
- `AccountManager`.

Без этого reasoning по проекту быстро уходит в ложные гипотезы.

## Подтверждённые точки пересечения

- `api/server.py` встраивает `traffic_hub` в общий web/API контур.
- `traffic_hub/services/autolead_bridge.py` читает legacy runtime data.
- `traffic_hub/services/job_runner.py` вызывает legacy `services/leads_service.py`.
- `utils/control_store.py` и `utils/license.py` держат одновременно новую и legacy совместимость.
- `utils/runtime_repository.py` уже выступает как boundary между частью верхних слоёв и legacy SQLite runtime.
- `utils/runtime_store_logs.py` уже отделяет `app_log` и `run_log` от общего god-file `utils/database.py`, но пока через compatibility facade.
- `utils/runtime_store_delivery.py` уже отделяет `send_history` и `retry_queue` от `utils/database.py`, также сохраняя старые импорты через facade.
- `utils/runtime_store_invites.py` уже отделяет `invite_history` и `invite_message_state` от `utils/database.py`.
- `utils/runtime_store_control_sync.py` уже отделяет `control_sync_queue` и retry/backoff-логику синхронизации от `utils/database.py`.
- `utils/runtime_store_leads.py` уже отделяет `leads` read/write/statistics path от `utils/database.py`.
- `utils/runtime_store_autofit.py` уже отделяет `autofit_seen` от `utils/database.py`.
- `utils/runtime_store_maintenance.py` уже отделяет cleanup/retention path от `utils/database.py`.
- `utils/runtime_store_schema.py` уже отделяет schema/init/migration path от `utils/database.py`.
- `api/dashboard_log_history.py` уже отделяет history-load и dashboard log normalization от `api/server.py`.
- `api/dashboard_assets.py` уже отделяет no-cache headers, asset version и HTML render helper-блок от `api/server.py`.
- `api/session_support.py` уже отделяет session/CORS helper-логику, login rate limit и session payload от `api/server.py`.
- `api/account_manager_bridge.py` уже отделяет живой redirect/token bridge для `AccountManager`, а исторический internal proxy path удалён как dead code.
- `api/routers/settings_bundle.py` уже отделяет import/export bundle helper-зону от `api/routers/settings.py`.
- `api/routers/settings_rabota.py` уже отделяет Rabota OAuth/token helper-зону от `api/routers/settings.py`.
- `api/routers/settings_sheets.py` уже отделяет Google Sheets/service-account helper-зону от `api/routers/settings.py`.
- `api/routers/settings_maintenance.py` уже отделяет cleanup/maintenance endpoint-зону от `api/routers/settings.py`.
- `api/routers/settings_core.py` уже отделяет основной editable/readonly/patch helper-каркас от `api/routers/settings.py`.
- `api/routers/settings_license_accounts.py` уже отделяет admin-only `license account` routes от owner-scoped settings flow в `api/routers/settings.py`.
- `utils/state.py` больше не должен импортировать `traffic_hub.config.settings` на module import ради одного `redis_url`; этот dependency переведён в lazy resolve path.

## Следствие

Проект уже контейнеризирован и operationally разделён, но кодовая база ещё не разведена до конца. Значит, главный путь улучшения сейчас:

1. Зафиксировать boundaries.
2. Убрать лишнее смешение source/runtime.
3. Вводить repository/service boundaries.
4. Только потом обсуждать физический перенос storage и крупный refactor.
