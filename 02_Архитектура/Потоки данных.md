# Потоки данных

## Основные потоки

- browser/dashboard -> `api/server.py`
- API request -> routers/services/runtime stores
- worker job -> queue -> subprocess-per-owner execution
- runtime state -> postgres/redis/runtime files -> websocket/dashboard

## Где чаще всего рвётся поток

- request принят web-layer, но owner-context теряется до service/repository;
- worker завершил job, но UI не увидел обновление из-за разрыва между runtime store и websocket/log feed;
- control store обновлён, а runtime artefact остался старым и продолжает влиять на поведение;
- диагностика читается не из того слоя: из archive/wiki вместо live runtime.

## Что проверять при отладке

- owner-scope данных
- источник истины по runtime state
- расхождение между control store, runtime store и UI
- где именно поток переходит границу `api -> services -> worker -> storage -> ws/ui`
