# Обзор системы

`TrafficHub` — не one-process и не one-db система.

## Подтверждённые узлы

- web/dashboard/auth/ws: `api/server.py`
- embedded product/API и router map: `traffic_hub/app.py`
- worker/queue execution: `traffic_hub/worker.py`, `traffic_hub/services/*`
- legacy business execution: `services/*`, `modules/*`, `utils/*`
- infra contour: postgres, redis, worker, account_manager, caddy, license services, standalone_content_bot

## Практическая модель системы

- web-layer принимает запросы, отдаёт dashboard/API и публикует часть realtime-сигналов;
- `api/server.py` является live entrypoint контейнера `autolead_bot` и одновременно встраивает `traffic_hub`-роутеры внутрь общего FastAPI-процесса;
- `traffic_hub/app.py` не является отдельной веб-инсталляцией в live сам по себе, а описывает product/API контур, который регистрируется из `api/server.py`;
- worker-layer исполняет owner-scoped jobs и пишет runtime-состояние;
- active `Autolead runtime` contour уже PostgreSQL-first и не должен описываться как SQLite-first слой;
- `traffic_hub` product DB — отдельный PostgreSQL-first contour для dashboard/auth/postback и связанных метрик;
- `control_store` — отдельный control contour с PostgreSQL backend и legacy `control.db` artefact trail;
- legacy-модули продолжают участвовать в бизнес-логике и не могут считаться “мертвым кодом” без проверки call-path.
- наличие `autolead.db` или `control.db` на volume само по себе не доказывает active backend.
- отдельный rewrite-контур не завершён: `traffic_hub/services/*` сосуществует с `services/*`, а не полностью заменяет его.

## Инварианты

- owner-scoped модель данных и исполнения является частью архитектуры;
- runtime и source repo надо отделять от внешнего wiki-layer;
- любые описания хранилища должны проверяться по live runtime и коду, а не по старым заметкам.

## Главные архитектурные риски

- путаница между control store и runtime store;
- смешение `Autolead runtime`, `traffic_hub` product DB и `control_store` в одну storage-модель;
- ложное допущение, что проблема локализуется только в web или только в worker;
- документирование по историческим заметкам без live-подтверждения;
- смешение product repo и knowledge repo в одном mental model.

## Audit 2026-06-23

- live `HEAD=5034c7b43`, GitHub checks green, контейнеры healthy, `/api/health` возвращает `control.backend=postgres`;
- полный test suite внутри `autolead_server_bot`: `310 passed, 43 skipped`;
- tenant-scoped таблицы в PostgreSQL имеют `tenant_id NOT NULL`, но часть SQLAlchemy models всё ещё объявляет `tenant_id nullable=True`;
- `traffic_hub/api/routers/integrations.py::_import_network_conversions` нарушает tenant boundary: создаёт `PostbackLog` без `tenant_id` и `owner_username`, что подтверждено live `NotNullViolationError`;
- role boundary не полностью самовосстанавливающийся: `control_license_users.Artem=user`, но `users.Artem=admin`;
