# Runtime logging

## Назначение

`utils/runtime_logging.py` решает, какие строки runtime-логов TrafficHub считаются полезными для пользовательской консоли. Это промежуточный фильтр между stdout worker/API, persistent `autolead_app_log` и realtime dashboard.

## Подтверждённые факты

- Источник кода: `/root/TrafficHub/utils/runtime_logging.py`.
- Persistent история логов хранится в runtime database, таблица `autolead_app_log`.
- UI показывает owner-scoped историю и live-события, а не весь stdout контейнера.
- Фильтр `is_ui_relevant_log()` сначала применяет drop-правила, затем keep-правила.

## Что нельзя отбрасывать

Для полного цикла Rabota.ru в UI должны проходить:

- старт фазы;
- строки API-запросов `[API] ...`;
- прогресс загрузки `⠋ Загрузка ...`;
- итог загрузки `✓ Загрузка ...`;
- итог Rabota.ru `[i] Rabota.ru: ...`;
- количество найденных, добавленных, пропущенных и обработанных лидов;
- актуальные строки заполнения анкет и ошибки заполнения.

## Почему это важно

Если фильтр скрывает рабочие строки, пользователь видит только `Полный цикл выполняется` и воспринимает задачу как зависшую. При этом worker может реально продолжать сбор и рассылку.

## Ограничения

- Фильтр не должен превращать UI в полный debug stdout.
- Технический шум можно скрывать, но нельзя скрывать прогресс фаз и итоговые счётчики.
- Для новых интеграций, например [[Zarplata.ru integration]], нужно отдельно проверять, что ключевые строки проходят через `is_ui_relevant_log()`.
