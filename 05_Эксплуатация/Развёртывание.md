# Развёртывание

## Подтверждённый deployment contour

- docker-compose product stack
- caddy как внешний reverse proxy/public entry
- отдельные контейнеры worker, account_manager, postgres, redis, license services

## Что важно

- live поведение проверять по контейнерам и health endpoints;
- изменение deployment без сверки runtime и логов недопустимо.
- backend reality проверять не по наличию `autolead.db`/`control.db` на volume, а по live env, container health и runtime status функций.
- live доступ начинать только через canonical SSH contour `[[05_Эксплуатация/Доступ и подключения]]`.

# Канон live-развёртывания

- Серверный git checkout: `/root/TrafficHub`.
- Сборка контейнеров выполняется только из `/root/TrafficHub/docker-compose.yml`.
- Контейнерный `/app` не является каноническим репозиторием: это build artifact и mutable runtime-layer.
- Постоянные данные и secrets остаются на host:
  - `/root/TrafficHub/data/runtime`
  - `/root/TrafficHub/data/logs`
  - `/root/TrafficHub/data/debug`
  - `/root/TrafficHub/data/backups`
  - `/root/TrafficHub/secrets`

# Правило деплоя

- Правки вносятся в `/root/TrafficHub`.
- Затем выполняются `docker compose build ...` и `docker compose up -d --force-recreate ...` из `/root/TrafficHub`.
- Hotfix напрямую в `/app` допустим только как аварийная временная мера; после этого изменения обязаны быть перенесены обратно в `/root/TrafficHub`.
