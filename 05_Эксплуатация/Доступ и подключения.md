## PowerShell-safe выполнение bash на live

PowerShell интерпретирует `$()`, `$var`, пайпы и кавычки до того, как команда попадёт на сервер. Поэтому сложные bash-команды нельзя писать inline в `ssh "..."`.

Канонический способ для простых команд без `$`, `$()`, `|` и вложенных кавычек:

```powershell
powershell -ExecutionPolicy Bypass -File "C:\Users\Арт\Desktop\Project\scripts\ssh_live_bash.ps1" -Command "cd /root/TrafficHub && git status -sb && git rev-parse --short=9 HEAD"
```

Канонический способ для любых сложных команд: только stdin here-string.

```powershell
@'
set -euo pipefail
cd /root/TrafficHub
echo "HEAD=$(git rev-parse --short=9 HEAD)"
docker compose ps
'@ | powershell -ExecutionPolicy Bypass -File "C:\Users\Арт\Desktop\Project\scripts\ssh_live_bash.ps1"
```

Запрещённые паттерны:

```powershell
ssh -F "C:\...\ssh\config" traffichub-live "cd /root/TrafficHub && echo HEAD=$(git rev-parse --short=9 HEAD) | cut -c1-9"
powershell -ExecutionPolicy Bypass -File "C:\...\scripts\ssh_live_bash.ps1" -Command "echo HEAD=$(git rev-parse --short=9 HEAD)"
```

Причина: `$(...)` и часть пайпа могут выполниться локально в PowerShell, а не на сервере.

## SSH hardening: confirmed 2026-07-15

- Глобальный effective policy: `PermitRootLogin no`, `PubkeyAuthentication yes`, `PasswordAuthentication no`, `KbdInteractiveAuthentication no`, `AuthenticationMethods publickey`.
- Запрет задан в начале `/etc/ssh/sshd_config`, до `Include /etc/ssh/sshd_config.d/*.conf`. Причина: `50-cloud-init.conf` задаёт `PasswordAuthentication yes`, а OpenSSH применяет первое найденное значение.
- UFW включён и стартует с host: default incoming `deny`; `22/tcp ALLOW`, `2222/tcp ALLOW`, `80/tcp ALLOW`, `443/tcp ALLOW`, включая IPv6.
- На 2026-07-18 канонический alias `traffichub-live` использует `2222`; alias `traffichub-live-22` оставлен как fallback.
- `sshd` запущен обычным `ssh.service`, а `ssh.socket` отключён: socket activation Ubuntu слушал только 22 и игнорировал дополнительный `Port 2222` при передаче готового socket.
- Automation drop-in `/etc/ssh/sshd_config.d/10-traffichub-automation.conf`: `Port 22`, `Port 2222`, `LoginGraceTime 30`, `MaxStartups 50:30:200`, `PerSourceMaxStartups 20`.
- `scripts/ssh_live_bash.ps1` повторяет только pre-auth подключения: удалённый bash сначала печатает уникальный ready-marker; после marker пользовательский скрипт никогда автоматически не запускается повторно.
- Перед любым изменением SSH/UFW необходимо оставить текущий key-based session открытым, выполнить `sshd -t`, затем проверить новый key-only SSH-сеанс и public `/api/health`.
