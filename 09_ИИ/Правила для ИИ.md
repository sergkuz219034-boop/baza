# Правила для ИИ

- сначала читать канонические страницы этой wiki;
- затем подтверждать факт кодом или runtime;
- не доверять archive без повторной верификации;
- различать confirmed fact и hypothesis;
- при изменениях в системе обновлять релевантные страницы канона.

## Обязательный порядок работы

1. Сначала читать `[[05_Эксплуатация/Доступ и подключения]]`, если задача затрагивает live server, deploy, runtime, логи или GitHub sync server repo.
2. Для live TrafficHub по умолчанию использовать только alias `traffichub-live` и principal `codex`.
3. Найти root-entrypoint по задаче.
4. Дойти до конкретного файла, контейнера, env или БД-факта.
5. Только после проверки обновлять wiki.
6. При расхождении между кодом и заметкой явно фиксировать, что именно устарело.

## Антипаттерны

- писать архитектурные выводы по памяти;
- пересказывать archive как будто это live truth;
- обновлять десять страниц одинаковым общим текстом вместо одного точного канонического узла;
- смешивать product repo, knowledge repo и server snapshot в один источник истины.
- спрашивать пользователя, как подключаться к live TrafficHub, пока не проверен canonical SSH contour из `[[05_Эксплуатация/Доступ и подключения]]`.
