# 2026-06-29 CRM русская локализация статусов и офферов

## Симптом

В таблице CRM пользователю показывались технические значения интеграций: `REJECTED` в статусе и `[sale]` в названии оффера.

## Зона системы

Dashboard TrafficHub, файл `/root/TrafficHub/dashboard/app.js`, секция CRM-лидов.

## Гипотеза

API отдаёт канонические значения из интеграций и БД, а UI выводит их без локализации.

## Проверка

На live-сервере проверен `dashboard/app.js`: таблица CRM-лидов вызывает `/traffic-api/leads`, затем рендерит поле `status` через `crmStatusText`, а поле `offer_name` выводит как обычный текст.

## Наблюдение

В `crmStatusText` не было маппинга для `rejected`, `approved`, `converted`, `duplicate`. Для оффера не было отдельного formatter, поэтому хвосты вида `[sale]` оставались английскими.

## Вывод

Правильное место исправления - слой отображения. БД и API должны сохранять исходные значения интеграций, чтобы не ломать синхронизацию и аналитику.

## Следующий шаг

Если появятся новые технические статусы от партнёрских сетей, добавлять их в UI-маппинг `crmStatusText` / `crmOfferText`, не переписывая исторические данные в БД.
