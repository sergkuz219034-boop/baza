# 2026-06-28 Zarplata.ru parsing through menu

## Симптом

Проверка парсинга лидов Зарплата.ру через меню TrafficHub показала, что job `zarplata` запускался и выгружал строки в Google Sheets, но в PostgreSQL `autolead_leads` сохранялось `0` лидов.

## Зона системы

- UI: `dashboard/app.js`, запуск команды `zarplata`.
- API/job queue: `api/routers/jobs.py`, `traffic_hub/services/job_queue.py`.
- Worker: `traffic_hub/services/job_runner.py`.
- Интеграция: `modules/zarplata_api.py`.
- Runtime DB: PostgreSQL таблица `autolead_leads`.

## Гипотеза

Проблема не в OAuth и не в меню, а в нормализации данных Зарплата.ру перед сохранением в общую таблицу лидов.

## Проверка

- OAuth admin проверен пользовательским access token.
- Job запущен тем же runtime-путём, что использует меню: `enqueue_job(owner='admin', command='zarplata', source='dashboard-smoke')`.
- Логи worker до фикса показывали `invalid input syntax for type integer` при сохранении лида.

## Наблюдение

Зарплата.ру отдаёт внешний resume id строкой вида `6d2881300010b7c5d500c2c9006d7376423463`. Общий слой `utils/runtime_store_pg_leads.py` пытался положить `raw.id` в integer-поле `response_id`, из-за чего PostgreSQL отклонял строку. Дополнительно `modules/zarplata_api.py::import_resumes` игнорировал пользовательский `per_page`, потому что default `20` перекрывал значение из конфига.

## Вывод

Меню и очередь работают. Первопричина была в storage boundary между внешним API Зарплата.ру и общей PostgreSQL-схемой Autolead.

## Исправление

- `modules/zarplata_api.py`: внешний строковый id сохраняется как `_source_id` и `_raw_data.external_resume_id`, а integer-поля получают только числовое значение или `0`.
- `utils/runtime_store_pg_leads.py`: integer-поля `vacancy_id`, `response_id`, `resume_id` проходят безопасное преобразование.
- `modules/zarplata_api.py`: `per_page` теперь берётся из owner-scoped настроек, если явно не передан аргументом.
- `tests/test_zarplata_api.py`: добавлены проверки строкового hex-id и owner-config `per_page`.

## Подтверждение

- Live job через runtime-контейнер: `found=1`, `normalized=1`, `saved=1`, `uploaded=1`.
