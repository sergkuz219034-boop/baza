## Симптом

- Модуль `Зарплата.ру` выглядел настроенным, но поиск резюме не работал.
- Для `artem` live-проверка `GET /resumes` возвращала `403 user_auth_expected`.
- Нужно было отдельно подтвердить, что логи Zarplata не теряются и видны во вкладке `Обзор`.

## Зона системы

- `api/routers/zarplata.py`
- `modules/zarplata_api.py`
- `traffic_hub/services/job_runner.py`
- `dashboard/app.js`
- PostgreSQL control store `control_user_app_configs`

## Гипотеза

- Кнопка получения `app token` перезаписывает основной `zarplata_ru.access_token`.
- После этого вместо user OAuth token модуль начинает ходить в `/resumes` с `client_credentials` token.

## Проверка

- В live-коде `api/routers/zarplata.py` endpoint `POST /api/zarplata/app-token` до фикса записывал токен в `zarplata_ru.access_token`.
- В live-runtime для `artem` в owner-config лежал токен с префиксом `APPL...`.
- Внутри контейнера `autolead_server_bot` вызов `ZarplataClient(token).me()` проходил, а `search_resumes()` возвращал `403` с `user_auth_expected`.
- В `traffic_hub/services/job_runner.py` stdout Zarplata-модуля идёт в owner-scoped лог через `_OwnerLogStream`.
- В `dashboard/app.js` функция `isVisibleLogMessage()` не фильтрует строки `Зарплата.ру`, значит они остаются видимыми в `Обзор`.

## Наблюдение

- Причина была подтверждена: `app token` и `user token` смешивались в одном поле.
- Это ломало поиск резюме у текущих пользователей, если кто-то нажимал кнопку получения токена приложения.
- Логи Zarplata в `Обзор` не теряются на фронтенде: они проходят общий log pipeline.

## Вывод

- Разделены два типа токенов:
  - `access_token` — только user OAuth token для `/resumes`;
  - `app_access_token` — отдельное поле для `client_credentials`.
- Добавлена автонормализация legacy-состояния:
  - если в `access_token` лежит `APPL...` и нет `refresh_token`, токен переносится в `app_access_token`, а `access_token` очищается.
- Выполнена миграция live-config: у `artem` legacy `APPL...` токен перенесён из `access_token` в `app_access_token`.

## Следующий шаг

- Пользователю нужно получить именно user OAuth token через `Авторизоваться` -> `code` -> `Получить токен`.
- Только после этого модуль `Зарплата.ру` сможет реально выполнять поиск резюме.
- Если понадобится автообновление карточек на `Обзор` сразу после завершения Zarplata-выгрузки, нужно отдельно расширить dashboard refresh triggers.
