# 2026-06-26 синхронизация LeadSU офферов для конверсий

## Симптом
В CRM-таблице TrafficHub в колонке `Оффер` отображался технический fallback вида `Оффер #982` вместо нормального названия оффера.

## Зона системы
- Backend: `/root/TrafficHub/traffic_hub/api/routers/integrations.py`
- БД: PostgreSQL таблицы `offers`, `conversions`, `postback_logs`
- Интеграция: LeadSU через `PartnerAPI` / `LeadsuAPI`
- UI: TrafficHub CRM, колонка `Оффер`

## Гипотеза
LeadSU postback/API-конверсии сохраняют `raw_data.offer_id`, но локальная таблица `offers` не синхронизирована, поэтому `conversions.offer_id` остаётся пустым и UI показывает fallback `Оффер #<id>`.

## Проверка
На live-сервере проверены таблицы PostgreSQL:
- `offers` изначально не содержала LeadSU офферы;
- `conversions.raw_data` содержала `offer_id`, например `982`, `10083`, `10963`, `11685`;
- часть `conversions.offer_id` была `NULL`.

## Наблюдение
После синхронизации LeadSU офферов и backfill старых конверсий несвязанных LeadSU-конверсий не осталось:
- `982` -> `Т-Банк HR [sale]`;
- `10083` -> `Voxys HR [sale]`;
- `10963` -> `Onecta HR [sale]`;
- `11685` -> `Тетрика - Трудоустроенный кандидат (Менеджер) HR [sale]`.

## Вывод
Root cause: импорт LeadSU-конверсий раньше не подтягивал список офферов до записи конверсий. Если `offer_name` отсутствовал в payload, система не могла связать конверсию с локальным `Offer`.

Исправлено на сервере:
- перед импортом LeadSU-конверсий вызывается `get_offers()`;
- офферы upsert-ятся в `offers` owner-scoped по `tenant_id` и `owner_username`;
- новые конверсии получают `conversions.offer_id` и `raw_data.offer_name`;
- старые конверсии довязываются backfill-логикой.
- server repo зафиксирован commit `3fd3f611b`.
