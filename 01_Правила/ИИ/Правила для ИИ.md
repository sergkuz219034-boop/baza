# Правила для ИИ

## Уточнения пользователя: независимость выполнения — 2026-10-16

- Полные циклы разных пользователей должны выполняться независимо, включая удалённый исполнитель RU. Проверка одной origin-очереди не доказывает параллельность всей цепочки. Общий фиксированный пул, заставляющий других owners ждать свободного слота, не соответствует этому требованию.
- Это правило относится ко всем текущим и будущим пользователям. Ограничения одной parent job на owner, provider rate limits, lease, idempotency и защита данных сохраняются. Независимость не означает бесконечную физическую мощность сервера.
- Источники и подключения равноправны: недоступное подключение не блокирует рабочие; если ни одно не работает, цикл должен остановиться до общей рассылки. Успешная проверка с нулём новых лидов не считается отказом. Уведомление должно назвать неработающее подключение и причину.
- Ручная остановка своей задачи — ожидаемое завершение, не ошибка. Нельзя этим правилом скрывать реальный сбой или замену чужой задачи.
- По запросу пользователя отчёты краткие, только по активным пользователям; вакансии — общий рейтинг по откликам за день, от большего к меньшему, включая нули.

Основание: прямые сообщения пользователя 15–16 октября в текущем чате. Реализация и ограничения: [[02_Код/Сущности/Redis job state]], [[02_Код/Архитектура/Интеграции]]. Текущий разрыв отчёта с runtime отмечен в [[04_План/Сейчас/Что происходит сейчас]].

- сначала через Graphify или `rg` найти узкий связанный подграф канонических страниц wiki, затем читать только релевантные узлы;
- затем подтверждать факт кодом или runtime;
- не доверять archive без повторной верификации;
- различать confirmed fact и hypothesis;
- при изменениях в системе обновлять релевантные страницы канона.
- **Graphify CLI** — навигационный ускоритель для вопросов по архитектуре кода и связям заметок: найти связанный подграф → прочитать минимум опорных узлов → подтвердить по первоисточнику. Это не Codex skill и не источник истины; fallback — `rg`, Obsidian-ссылки и проверка live-кода/runtime.
- **иерархия моделей**: слабая → простые задачи, средняя → средние, мощная → сложные. Не использовать мощную модель там, где хватит слабой.

## Политика резервных копий — уточнения пользователя 2026-10-12

TrafficHub создавать резервную копию только перед рискованным обновлением или изменением БД, без ежедневного расписания. Позднее в этом чате пользователь уточнил: «бекап храни локально у меня в папке, а на серверах бекапы удали». Место хранения: `C:/Users/admin/Desktop/Project/backups/2026-10-12/` (для следующих дат — соседние датированные каталоги). Это отменяет прежнее постоянное хранение на origin и RU; неизменным остаётся требование проверенной копии перед рискованным действием.

На сервере допустима только временная согласованная выгрузка для переноса. Сначала сохранить данные локально, сверить серверные SHA256, полностью проверить gzip/SQLite и затем удалить серверные экземпляры. Локальные файлы, настройки и данные не включать в Git/wiki/публичные логи; папка защищена ACL пользователя. Рабочие БД, Redis RDB/AOF в активных томах и ключи доступа являются рабочими данными, а не резервными копиями, и не входят в удаление backups.

`deploy/traffichub_postgres_backup.sh` теперь готовит временный dump+globals+SHA и завершает подготовку кодом 75, блокируя рискованное продолжение до локального подтверждения. `deploy/local_backup_custody.py` сверяет свежий запрос и локальный receipt, отвергает несовпадения/устаревшие данные/повторное использование и удаляет подтверждённую серверную выгрузку. `deploy/with_verified_postgres_backup.sh` и migration hook сохраняют этот gate. При недоступном компьютере рискованное обновление не выполнять. Безопасные изменения статического UI не требуют новой копии.

TrafficHub timer остаётся disabled/inactive; серверное ежедневное расписание Focus Group также отключено по уточнённой политике хранения. Ручная копия Focus Group создаётся временно для локального переноса, отправка на origin отключена. Это разовое поручение на очистку старых серверных копий не вводит автоматическое удаление локальных архивов. Доказательства изменения политики и проверок: `C:/Users/admin/Desktop/Project/outputs/server-cleanup-20261012/`; текущий перенос и финальное удаление требуют отдельного подтверждения runtime в итоговом EVIDENCE.
