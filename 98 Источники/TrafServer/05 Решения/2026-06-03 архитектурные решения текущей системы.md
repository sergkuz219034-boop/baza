# 2026-06-03 архитектурные решения текущей системы

Теги: #решение

## Решение 1

### Проблема

Нужно отделить пользовательские данные разных операторов в shared runtime и shared API.

### Контекст

Система хранит данные в нескольких БД и эволюционно переходила от shared-схемы к owner-scoped модели.

### Решение

Использовать `owner_username` как основной multi-tenant ключ в runtime БД, TrafficHub моделях и API scoping.

### Последствия

- операторы изолированы на уровне данных;
- admin сохраняет глобальную видимость;
- миграции и тесты tenant isolation становятся критически важными.

### Альтернативы

- отдельная БД на пользователя;
- изоляция только на UI-уровне

## Решение 2

### Проблема

Google Sheets как control plane плохо подходит для лицензий и конфигов.

### Контекст

В коде виден переход на `control.db`, но сохранена совместимость с legacy-хранилищем.

### Решение

Сделать `control.db` primary source для лицензий, per-user config и auth payloads, оставив compatibility layer в `license.py`.

### Последствия

- локальная работа надёжнее;
- миграционный код остаётся сложным;
- legacy compatibility увеличивает сопровождение.

### Альтернативы

- полный отказ от legacy сразу;
- оставить Google Sheets единственным источником

## Решение 3

### Проблема

Операционный runtime и business API решают разные задачи, но должны жить рядом.

### Контекст

`main.py` поднимает scheduler/runtime, а `traffic_hub/app.py` строит отдельный `/traffic-api/*` контур.

### Решение

Сохранить разделение на operational Autolead контур и business TrafficHub контур внутри одного deployment.

### Последствия

- проще эволюционировать бизнес-сущности отдельно;
- выше когнитивная нагрузка для новых инженеров;
- документация должна явно разделять контуры.

### Альтернативы

- объединить всё в один backend;
- вынести TrafficHub в полностью отдельный репозиторий

## Решение 4

### Проблема

В deployment несколько сервисов имеют разные auth-perimeter и разные потребности в публикации.

### Контекст

Compose и Caddy публикуют `autolead_bot`, `license_auth`, `account_manager` и AI perimeter.

### Решение

Оставить loopback binding для внутренних сервисов и публиковать их наружу только через Caddy.

### Последствия

- меньше прямых публичных поверхностей;
- конфигурация Caddy становится критической частью безопасности.

### Альтернативы

- публиковать каждый сервис напрямую;
- использовать отдельный ingress вне хоста
