# 2026-06-11 local clones forbidden workspace policy

Теги: #решение

## Проблема

Локальная машина одновременно использовалась и как Obsidian vault для расследований, и как место для рабочих git-клонов TrafficHub. Из-за этого в `TrafServer` и рядом с ним накапливались source trees, runtime vendor directories, локальные БД и временные backup-артефакты.

Это приводило к трём типам проблем:

- wiki workspace переставал быть чистой инженерной картой;
- Obsidian ломался на служебных runtime-папках;
- источник истины размывался между локальным clone, server runtime и GitHub.

## Контекст

- рабочий production/runtime код живёт на сервере в `/root/TrafficHub`;
- GitHub нужен как удалённая история и backup;
- локальный `TrafServer` нужен для wiki, SSH-утилит и reverse engineering;
- локальный clone `TrafficHub-github` больше не нужен как постоянная рабочая копия.

## Решение

Принята жёсткая модель:

- локальные git-клоны TrafficHub на машине запрещены как постоянный инструмент;
- любые изменения кода выполняются только в серверном repo `/root/TrafficHub`;
- `TrafServer` хранит только:
  - wiki,
  - SSH-ключи,
  - server-side утилиты,
  - snapshots / mirrors для расследований;
- runtime/state файлы и vendor/runtime каталоги выносятся во внешнее техническое хранилище вне vault;
- временные backup-файлы на сервере хранятся вне repo, например в `/root/TrafficHub_backup_archive/<date>/`.

## Последствия

Положительные:

- Obsidian vault остаётся чистым и не ломается на runtime-мусоре;
- источник правды для кода становится однозначным: серверный repo + live runtime;
- GitHub синхронизируется из одного места, а не из локального clone и сервера вперемешку.

Ограничения:

- для push с сервера нужна стабильная GitHub-аутентификация;
- любая работа с кодом теперь требует server access;
- локальные read-only snapshots нельзя путать с рабочим repo.

## Альтернативы

### 1. Держать локальный clone вне `TrafServer`

Отклонено. Это уменьшает мусор внутри vault, но сохраняет раздвоение источника кода между локальной машиной и сервером.

### 2. Держать локальный read-only архив исходников

Допустимо только как временный экспорт или cold backup, но не как постоянный рабочий процесс.

### 3. Оставить всё как есть

Отклонено. Уже привело к operational drift, runtime-мусору в vault и поломке Obsidian на служебных каталогах.

## Применение

- локальный clone `TrafficHub-github` удалён;
- runtime/state файлы вынесены из `TrafServer` во внешнее storage;
- локальный README и плейбуки обновлены под server-only режим.
