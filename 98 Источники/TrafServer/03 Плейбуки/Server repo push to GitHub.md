# Server repo push to GitHub

Теги: #плейбук

## Назначение

Плейбук для отправки изменений из серверного репозитория `/root/TrafficHub` на GitHub без локального clone.

## Канон

- рабочий repo: `/root/TrafficHub`
- удалённая история: GitHub `origin`
- локальный `TrafServer`: только wiki и утилиты

## Минимальная последовательность

1. Подключиться к серверу.
2. Перейти в `/root/TrafficHub`.
3. Проверить:
   - `git status`
   - `git remote -v`
   - наличие рабочего доступа к GitHub
4. Убедиться, что в repo нет временных `.bak_*`.
5. Выполнить commit.
6. Выполнить push в `origin`.
7. Проверить, что GitHub получил commit.
8. Обновить локальную wiki по фактическому результату.

## Требования к аутентификации

Допустим только один стабильный способ:

- либо SSH key / deploy key;
- либо HTTPS remote с PAT.

Выбранный способ нужно держать единым и документированным. Смешанный ручной режим не считается устойчивым.

## Что делать, если push не работает

Если `git fetch` / `git push` падает по auth:

1. проверить тип remote;
2. проверить, что серверный ключ действительно привязан к GitHub;
3. если используется HTTPS, проверить PAT и scope;
4. не обходить проблему созданием локального clone.

## Что считать завершением

- commit есть в `/root/TrafficHub`;
- этот commit виден в `origin/main`;
- локальная wiki обновлена;
- локальный source clone при этом не создавался.
