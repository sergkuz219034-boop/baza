# Server-only development

Теги: #плейбук

## Назначение

Плейбук для режима, в котором локального git-clone TrafficHub нет, а любые изменения кода делаются только через серверный repo `/root/TrafficHub`.

## Базовые правила

1. Не создавать локальный clone рядом с wiki workspace.
2. Не распаковывать app source внутрь `TrafServer`.
3. Любые правки кода делать только на сервере.
4. После каждой существенной правки синхронно обновлять локальную wiki.

## Рабочая последовательность

1. Подключиться к серверу через локальные SSH-утилиты.
2. Перейти в `/root/TrafficHub`.
3. Проверить текущее состояние:
   - `git status`
   - нужные контейнеры
   - нужные runtime-файлы и логи
4. Изучить код и live-поведение.
5. Внести правки на сервере.
6. Проверить контейнеры, endpoint-ы, логи и runtime-поведение.
7. Закоммитить изменения в серверном repo.
8. Отправить изменения на GitHub.
9. Обновить локальную wiki в `TrafServer`.

## Что запрещено

- хранить `.bak_*` рядом с tracked code;
- использовать локальный Obsidian vault как workspace для исходников;
- оставлять временные runtime/vendor директории внутри `TrafServer`;
- считать `remote_files/` или `remote_server_snapshot/` полноценным рабочим repo.

## Backup перед risky hotfix

Если нужна страховка перед точечной правкой:

1. не создавать `.bak_*` внутри `/root/TrafficHub`;
2. складывать backup вне repo, например:
   - `/root/TrafficHub_backup_archive/<date>/...`
3. если нужен diff bundle, хранить его отдельно от tracked tree.

## Проверка после задачи

- `git status` на сервере понятен и не засорён мусором;
- live runtime действительно работает с новой логикой;
- GitHub синхронизирован;
- локальная wiki отражает фактическое текущее состояние.
