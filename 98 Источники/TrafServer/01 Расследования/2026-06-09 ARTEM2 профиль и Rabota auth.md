# 2026-06-09 ARTEM2 профиль и Rabota auth

## Симптом
Попросили создать отдельный профиль `ARTEM2`, привязать к нему Rabota.ru и выгрузить лиды за `07.06.26–09.06.26` без создания новых вкладок в Google Sheets.

## Зона проекта
- `utils/control_store.py`
- `services/leads_service.py`
- container runtime `/app/data/runtime/secrets`

## Гипотеза
Если завести отдельный login `ARTEM2` в control store и привязать к нему свой runtime-secrets, профиль будет изолирован от `alex`, а выгрузка пойдёт в уже существующие листы.

## Проверка
1. Создан отдельный логин `ARTEM2` в container control store.
2. Скопирован рабочий профиль `artem` как базовый шаблон.
3. Зафиксированы существующие spreadsheet ID:
   - pending: `1eE9UHnnyyFSchwYgJjG2O4L3dwm6jdhwcJplAT6xHRk`
   - processed: `10tCmh8ZFbHhmNohrZRNedfY81K2_olYJnjk623HRnMY`
4. Проверены реальные вкладки в таблицах:
   - pending workbook: `Все лиды`
   - processed workbook: `Резюме`
5. Запущена пробная выгрузка под `ARTEM2` в изолированном контейнерном процессе.

## Наблюдение
- Профиль `ARTEM2` создался отдельно и не затронул `alex`.
- При правильных spreadsheet ID синк целится в существующие листы `Все лиды` и `Резюме`, без автосоздания новых вкладок.
- Rabota.ru API для переданного токена отвечает `401` и требует повторной авторизации.
- Из-за этого сбор лидов вернул `0`, а выгрузка не добавила строк.

## Вывод
Изоляция профиля и маршрутизация в Google Sheets настроены правильно.
Блокер выгрузки сейчас не в `ARTEM2`, а в невалидном/просроченном Rabota.ru access token.

## Следующий шаг
- Повторно авторизовать Rabota.ru для `ARTEM2` через Dashboard → Настройки → API Token.
- После получения валидного токена повторить сбор и выгрузку в тех же листах.
