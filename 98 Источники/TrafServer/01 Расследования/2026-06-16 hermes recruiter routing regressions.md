# 2026-06-16 Hermes recruiter routing regressions

Теги: #расследование #hermes #telegram #recruiting

## Симптом

- В live-диалоге Виктория повторяла уже предложенную `Тетрику` на реплику `а какие еще есть вакансии?`.
- Реплика `есть что-то с чатами?` не переводила кандидата в правильную ветку `Т-Банка` и могла увести дальше по цепочке.
- В ветке `Т-Банка` короткий ответ городом (`Москва`) не всегда приводил к региональному ответу.
- Сервисные фразы вроде `расскажите подробнее` иногда ошибочно попадали в поле `city`.

## Зона системы

- `tools/hermes_telegram_user_bridge.py`
- deterministic routing layer
- recruiter vault `docs/hermes-victoria-vault`

## Гипотеза

- Проблема не в общих vacancy rules, а в узком наборе phrase match-правил внутри deterministic layer.
- Живые формулировки кандидата не попадали в распознавание `other vacancies / wants chats / city follow-up`, поэтому мост отдавал ход свободной генерации и терял state-aware routing.

## Проверка

- Локально воспроизведён сценарий:
  - `Был / Рассматриваю / от 6 часов / Московская область`
  - `а какие еще есть вакансии?`
  - `есть что-то с чатами?`
  - `Москва`
- Прочитаны и проверены ветки:
  - `_extract_city_answer(...)`
  - `_deterministic_reply(...)`
  - `_should_force_deterministic_first(...)`
  - `_next_vacancy_after_rejection(...)`
- Локально подтверждено, что до правки:
  - `а какие еще есть вакансии?` не матчилась в forced branch;
  - `есть что-то с чатами?` не считалась chat-request вариантом;
  - `расскажите подробнее` извлекалось как `city`;
  - голый город внутри уже предложенного `Т-Банка` не имел отдельной deterministic ветки.

## Наблюдение

- В bridge не хватало явных helper-правил под естественные формулировки кандидата:
  - `_asks_other_vacancies(...)`
  - `_asks_chat_variant(...)`
- Ветка `Т-Банка` не имела отдельного follow-up на уже известный или только что присланный город.
- Из-за этого фразы `Москва`, `Челябинск`, `есть что-то с чатами?` и `а какие еще есть вакансии?` обрабатывались нестабильно.
- После правки:
  - `а какие еще есть вакансии?` детерминированно переводит на следующий оффер;
  - `есть что-то с чатами?` в ветке `Т-Банка` больше не считается отказом, а честно объясняет `чаты + звонки`;
  - `Москва` в ветке `Т-Банка` отдаёт корректный fallback без выдуманной суммы;
  - `Челябинск` подставляет доход `67000` из [[07 T-Bank Cities]];
  - `расскажите подробнее` больше не затирает `city` и переводится в vacancy detail.

## Вывод

- Root cause был в phrase-level routing gaps внутри Python bridge, а не в отсутствии знаний у Hermes по вакансиям.
- Для recruiter-сценария Hermes не должен оставаться один на коротких переходных репликах кандидата; такие реплики лучше закрывать детерминированно по state и vault.

## Следующий шаг

- Выкатить обновлённый `tools/hermes_telegram_user_bridge.py` на live-сервер.
- Перезапустить `hermes-user-bridge.service`.
- Прогнать live-check по сценариям:
  - `Тетрика -> а какие еще есть вакансии?`
  - `Онекта -> есть что-то с чатами?`
  - `Т-Банк -> Москва`
  - `Т-Банк -> расскажите подробнее`
